# 워치 운동 중 화면 — 현행 캡처와 11개 구성 시안

2026-10-15. 사용자가 현행 워치 운동 중 화면과 변경 시안 3개를 요청했다.
선택 전 비교 자료이며 앱 코드 또는 배포에 적용하지 않았다.

## 현행 캡처의 근거

ADB 연결 기기가 없어 실물 화면을 캡처하지 못했다.
main `7aacd78`의 Wear 0.2.7 MainActivity 소스를 클래스명만
PublishedWatchPreviewActivity로 치환한 임시 테스트 fixture로 실행하고,
Robolectric native graphics에서 실제 Android View를 432×432px/216×216dp로 렌더링했다.
별도 브랜치의 이전 두 페이지 수정본을 현행 화면으로 제시하지 않았다.
소스 SHA-256과 비교용 상태 값은 provenance.json에 기록했다.

운동명 덤벨 컬, 현재 1세트, 10kg, 목표 20회, 현재 8회, 심박 112는
화면 비교용 합성 값이다. 시안의 현재 시각 10:09도 예시이며 실제 측정 값이 아니다.
현행 원본 PNG는 앱 뷰 그대로이며, 비교판에서는 실물의 원형 영역을 모사해 표시한다.
현행 화면은 해당 크기에서 고정된 상단 내용 때문에 하단 입력 영역이 눌려 보인다.

## 3개의 차이

- A: 현재 횟수 8을 최우선으로 두고 운동명/현재 세트/중량, 목표, 심박을 세로로 배치.
- B: 중량과 자동 횟수를 나란히 묶어 이번 세트의 조건을 함께 확인.
- C: 현재 횟수와 목표를 함께 두고 8/20의 진행을 링으로 표시. 확률·정확도 표시가 아니다.

세 안은 정보 종류와 색을 공통으로 유지해 배치와 크기를 비교할 수 있게 했다.
주 횟수 40sp, 운동명 16sp, 필수 보조 정보 12sp. B의 중량은 28sp.
정상 연결 문장/큰 로고/템포 설명/업데이트/상시 입력 버튼은 첫 화면에 넣지 않았다.
아래로 넘기는 전체 추가 정보 페이지는 후속 구성 대상이며, 이번 이미지는 운동 중 첫 화면만 보여준다.
완료/보정/수동 기록의 서비스 계약은 아직 바꾸지 않았다.

## 생성 및 확인

WatchDesignSnapshotTest.kt는 디자인 캡처 harness이며 production 소스 또는
일반 테스트 소스 세트에 두지 않았다. 필요한 경우 디자인 파일을 임시 test 소스에 복사하고,
현재 main 소스의 클래스명을 위와 같이 치환한 fixture를 만든 뒤
`:wear:testDebugUnitTest --tests '*WatchDesignSnapshotTest'`만 실행한다.
임시 fixture/harness는 생성 후 제거했다.

이번 캡처 task 1개는 성공했다. 전체 테스트/lint/OTA APK 빌드/공개 배포는 수행하지 않았다.
PNG를 직접 열어 한글, 같은 상태 값, 원형 영역에서의 잘림을 확인했다.
실기기 동작 또는 설치된 APK의 화면과 일치 여부를 확인한 결과는 아니다.

## D2 아래로 넘긴 두 번째 화면 — 구성 제안

사용자가 아래로 넘긴 화면도 요청해 운동 중의 두 번째 전체 화면을 추가로 제안했다.
운동명/현재 세트/현재 횟수를 확인할 수 있게 두고, 두 가지 동작을 48dp 높이로 분리했다.

- 세트 마치기: 기록될 횟수 `8회로 기록`을 같이 표시한다.
- 횟수 수정: 현재 횟수의 편집으로 들어간다. 이 조작만으로 세트 완료를 보내는 흐름은 피한다.

아래의 작은 위쪽 화살표와 안내는 횟수 화면으로 돌아가는 방향을 나타낸다.
템포/업데이트/정상 연결 문장은 운동 중 두 번째 화면에도 나열하지 않았다.
총 운동 시간이나 다음 운동 목록처럼 현재 Activity에 없는 정보는 임의로 넣지 않았다.

현재 앱의 showManualCount는 상태에 따라 COMPLETE/EDIT를 한 편집 흐름에서 전송한다.
따라서 두 동작은 기존 함수에 이름만 바꿔 연결할 수 없으며, 구현 시 편집과 완료 시점을
구분해 현재 세트 식별자/횟수로 폰 권한의 기록 흐름에 연결해야 한다.
이번 그림의 버튼은 동작 연결 없이 그린 구성 제안이며 앱 소스를 변경하지 않았다.

`draft-d2-details.png`와 `comparison-d2-pages.png`를 생성하고 원형 화면의 텍스트/버튼을 확인했다.
전용 렌더링 task `renderD2WithTheWholeSecondPage`만 실행했다.
