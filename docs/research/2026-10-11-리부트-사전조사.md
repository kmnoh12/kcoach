# KCoach 리부트 사전조사 (2026-10-11)

목표 재확인: 손등 위 워치 하나로 위 리모컨처럼 손목 움직임을 3D로 재현하고(궤적·각도·회전), 반복수와 속도까지 판정한다. 워치는 신호 송수신만, 계산은 폰.

## 1. 손목 3D 재현은 어디까지 가능한가

| 항목 | 가능성 | 근거 |
|---|---|---|
| 손목 각도·회전(3D 자세) | 높음 | 가속도+자이로 융합은 짧은 구간에서 안정적. 위 모션플러스도 자이로로 회전을 잡았다 |
| 반복 1회 안의 상대 궤적 모양 | 중간, 실측 필요 | 이중적분 오차는 몇 초 넘으면 커지지만 짧은 구간은 정확할 수 있음. 골프 퍼팅 연구는 정지 순간(어드레스·백스윙 탑·피니시)에 속도 0으로 리셋. 반복의 상·하단 정지점이 같은 역할 |
| 절대 좌표(cm 단위 위치) | 낮음~중간 | 위 리모컨도 위치는 IR 센서바(외부 기준) 덕분. 워치 단독 팔 추적 연구(ArmTrak) 중앙오차 약 9~13cm, 서 있을 때 조건 |
| 캘리브레이션 없는 팔 자세 | 연구 단계 | ArmPoser(2026-09 preprint), RTAT(SenSys'22, 폰에서 추론) |

결론: "반복마다 0점 리셋하는 상대 궤적 + 3D 회전"은 현실적 목표. 절대 위치는 표시용 근사로만.

## 2. 통신량은 병목이 아니다 (계산값, 미실측)

6축 float32 + 타임스탬프 ≈ 32바이트/샘플. 100Hz면 약 3.2KB/s. 블루투스로 충분한 수준.
진짜 리스크는 통신량이 아니라 아래 두 가지.
- 화면 꺼짐 시 삼성의 서드파티 포그라운드 센서 수집 제한 보고(Galaxy Watch4 포럼). Health Services도 앰비언트에서 데이터를 배치로 묶음.
- 배터리.

Data Layer: ChannelClient = 양방향 스트림 파이프(연속 전송용), MessageClient = 재시도 없는 best-effort. 공개된 지연 벤치마크는 못 찾음 → 직접 측정.

## 3. 반복 카운팅

- 공개 데이터셋: MM-Fit(스마트워치 포함, 반복 라벨), Gym Gesture(손목 IMU 100Hz, 체스트플라이·체스트프레스·랫풀다운·시티드로우·트라이셉 익스텐션, 반복 라벨).
- 스마트워치 딥러닝 카운팅 연구: 세트의 91%에서 ±1회 이내.
- 실제 Watch8 최대 샘플링은 공개값 없음 → `getMinDelay()`와 실측 타임스탬프로 확인.
