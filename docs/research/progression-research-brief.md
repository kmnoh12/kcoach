# 연구 지시서: 점진적 과부하 알고리즘 근거 조사

**역할:** 조사와 검토만 한다. 코드, 파일을 수정하지 않는다. 결과는 마지막 메시지로 한국어 마크다운으로 낸다.

## 배경
워치(손목 IMU) 기반 웨이트 기록 앱 "워치짐". 점진적 과부하를 앱이 **LLM 없이 규칙 기반**으로 자동 진행한다. 켜면 모든 운동에 적용되고, 사용자는 속도 슬라이더(느리게/보통/빠르게)만 조절한다. 다음 루틴을 열 때 이미 올라간 목표가 입력칸에 채워져 있어야 한다(추천 팝업이 아니라 미리 적용).

현재 코드: `core/.../ProgressionEngine.kt`, `ExerciseHistory.kt`의 `NextTargetAdvisor`. 계획 횟수를 상한, 상한-2를 하한으로 보고 한 개의 증량 단위(20kg 이상 2.5, 미만 1.0)만 쓴다. 세트별 목표, 웜업 구분, 장비별 증량 단위, 1RM 추정은 없다. 먼저 읽고 현재 동작을 확인하라.

## 우리가 정한 설계안 (검증 대상)
1. **횟수 먼저, 무게 나중** (이중 점진). 예: 벤치 80kg 5회 → 6 → 7 → 8회 상한 도달 시 85kg × 약 5회로 증량. 세트별로 따로 적용(예: 60×10, 60×10, 80×7처럼 세트마다 횟수가 다른 구조도 처리). 웜업 세트는 제외.
2. **실패 시 무게를 줄이지 않고 유지.** 연속 실패 시에도 앱은 자동으로 낮추지 않고 제안만.
3. **장비별 증량 단위:** 바벨은 5kg 또는 10kg만(한쪽 원판 2.5/5kg). 덤벨은 1~2kg. 핀 머신·케이블은 핀 한 칸(크기는 사용자 기록에서 서로 다른 무게의 이웃 차이 최빈값으로 추정, 부족하면 한 번 질문).
4. **추정 1RM을 공통 진행 지표로** 쓸 것을 검토 중: 증량 후 목표 횟수는 추정 1RM이 비슷하게 유지되는 횟수(예: 30kg×10 → 35kg×약 5). 계산 횟수가 너무 낮으면(약 4~5회 미만) 한 단계 작은 증량 단위로 내림. 센서 횟수는 신뢰하고 사용자가 고치면 우선.
5. 후반 속도 저하 등 파형 신호는 "참고 신호"로만 사용.

## 조사 질문 (근거와 출처를 각각 붙일 것)
1. **ACSM 2009 입장문** "Progression Models in Resistance Training for Healthy Adults" 본문에서 증량 기준(몇 % / 몇 회 초과 / 몇 번 연속)을 원문으로 확인하라. 내 기억은 "1~2회 초과를 2회 연속 달성 시 2~10% 증량"이지만 미확인이다. 더 최신 ACSM 입장문(2026)이 있으면 차이도 알려라.
2. **이중 점진, 2-for-2 규칙 등 실무 규칙**의 출처. 논문으로 뒷받침되는 것과 코치들의 경험칙을 구분하라.
3. **1RM 추정 공식**(Epley, Brzycki, Lombardi, Mayhew 등)의 오차를 반복 횟수 구간(1~5, 6~10, 11~15, 15+)과 운동 종류(바벨 복합, 덤벨, 머신 고립)별로 정리하고, 어떤 공식을 어느 횟수까지 쓰는 게 합리적인지 권고하라. 손목 센서가 횟수를 ±1 틀릴 때 추정 1RM 오차도 계산하라.
4. **우리 설계 검증:** (a) 5·10kg 고정 증량이 어떤 종목·부하에서 비현실적인지(예: 20~40kg 바벨 컬, 가벼운 바벨 운동), (b) "횟수 상한 도달 후 증량하면서 횟수를 되돌림" 방식이 추정 1RM 기준으로 일관적인지, (c) 증량 후 목표 횟수를 어떻게 정하면 실패율이 낮은지.
5. **세트별 이중 점진**을 피라미드·역피라미드·백오프 세트 구조에 적용할 때 흔한 실무 규칙이나 함정.
6. **속도 슬라이더** 매핑 제안: 3~5단계로 각각 어떤 조건(상한 도달 횟수, 증량 크기, 필요한 연속 성공 횟수)을 쓰면 되는지 표로.
7. **맨몸·수동 입력 운동**(풀업, 레그프레스 등)의 진행 규칙. 가중 풀업 포함.
8. **정체기 처리** (몇 번 연속 진전이 없을 때 무엇을 제안할지)와 디로드의 앱 내 표현 방식.

## 출력 형식
- 결론 요약 (설계안 각 항목 "근거 있음 / 경험칙 / 근거 못 찾음 / 수정 권고")
- 질문별 상세 + 출처 링크 (논문은 저널·연도, 웹은 URL)
- 엔진에 바로 넣을 수 있는 **규칙 표** (조건, 행동, 수치) 초안
- 확인하지 못한 것과 불확실한 부분을 명시
