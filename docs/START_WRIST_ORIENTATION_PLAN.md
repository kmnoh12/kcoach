## 현재 사실과 관측 범위

현재 StartPoseStabilityGate는 정지한 가속도 방향을 상대 기준으로 잡고 2초 안정 여부만 본다.
임의의 안정된 방향이 운동의 올바른 시작 자세인지 확인하지 않는다. 정지한 자이로 값은 각속도라
작아지며 절대 자세를 직접 주지 않는다. 준비 방향에는 저역통과한 중력 방향/가속도와 필요시 회전벡터,
준비 방향으로 들어오는 움직임에는 자이로를 쓴다.
근거: [Android 운동 센서](https://developer.android.com/develop/sensors-and-location/sensors/sensors_motion),
[센서 좌표계](https://developer.android.com/develop/sensors-and-location/sensors/sensors_overview).

중력 방향으로 워치 화면의 위/아래 기울기와 손목의 수직/수평 방향은 구분할 수 있다.
중력 축 주위의 수평 회전은 중력만으로 구분되지 않는다. 특히 팔을 아래로 내린 자세에서
손바닥이 몸 쪽인지 정면인지 같은 차이를 중력 벡터 하나로 판정하지 않는다.
손목 들기/AOD 전환은 특정 움직임·끝 방향을 패턴화할 수 있다는 예시로 취급한다.
그 예시를 모든 운동의 정자세나 어깨·팔꿈치 위치 판별 능력으로 승격하지 않는다.

`랫풀의 그립 차이는 워치로 절대로 알 수 없다`고 일반화하지 않는다. 전완이 수평이면 전완 회전에
따라 중력의 기기 축 성분이 바뀌어 손바닥 위/아래를 구분할 수 있다. 전완이 중력 축과 나란하면
같은 회전이 중력 방향을 거의 바꾸지 않아 구분이 어렵다. 랫풀의 시작 팔 높이·손잡이·손목 굽힘이
달라지는 상황에서 이 차이를 운동 이름만으로 올바른 그립이라고 해석하지 않는다.
회전벡터를 추가해도 확인한 시작 기준 없이 손목 방향에서 팔꿈치·몸통 자세를 복원할 수는 없다.
헬스장 철제 기구 주변의 지자기 품질과 상대 회전의 누적 오차도 검증 전에는 가정하지 않는다.

워치 한 개로 팔이 몸에 붙었는지, 팔꿈치가 제 위치인지, 양팔이 동시에 준비됐는지는 확정할 수 없다.
UI는 `준비 손목 방향 확인`이라고 표시하고 `정자세 확인/완벽한 자세`라고 표시하지 않는다.

## 첫 적용 후보와 공유할 검진기

| 후보 그룹 | 처음 적용할 수행 변형 | 워치에서 확인할 것 | 확인할 수 없는 것 |
|---|---|---|---|
| H-UP | 사용자가 지정한 케이블 익스터널 로테이션: 손바닥 위·손목/전완 수평에 가까운 시작 | 확인한 착용 조건에서 워치 화면 법선의 위/아래 방향, 중력 벡터·낮은 각속도 2초 | 상완 고정·팔꿈치 90도·몸통 반동 |
| H-DOWN | 사용자가 지정한 케이블 크로스오버 리버스 플라이: 손등 위 그립 | 위 그룹과 반대 화면 법선 및 확인한 시작 손목 기울기, 안정 2초 | 팔의 높이·벌어진 정도·견갑 위치 |
| ARM-DOWN | 덤벨 레터럴 레이즈: 기본 뉴트럴 그립·팔 내린 시작 | 확인한 손목 세로 방향·중력 벡터, 안정 2초 | 팔이 몸에 닿았는지·양팔 위치·허리/어깨 자세 |

이 셋은 종목 이름 전체에 대한 보편 정답이 아니다. 사용자가 지정/확인한 수행 변형에만 적용한다.
익스터널 로테이션의 다른 그립이나 리버스 플라이의 뉴트럴/다른 케이블 높이는 자동으로 같은 그룹에
넣지 않는다. 덤벨 레터럴 레이즈의 기본 뉴트럴 시작은 [ACE 설명](https://www.acefitness.org/resources/everyone/exercise-library/26/lateral-raise/)과도 맞는다.
케이블 레이즈는 [ACE 단일 팔 예시](https://www.acefitness.org/resources/everyone/exercise-library/354/single-arm-lateral-raise/)처럼 케이블과 손이 몸 앞을 가로지를 수 있어 덤벨과 시작 조건을 바로 통합하지 않는다.

H-UP/H-DOWN은 같은 중력 방향 검진기를 쓰고 목표 방향 조건만 분리한다.
ARM-DOWN은 향후 서서 팔을 내린 컬/해머 컬의 관측 가능한 기울기 검사와 코드를 공유할 수 있지만,
손바닥 방향이 같다는 뜻은 아니다. 초기 적용은 덤벨 레터럴 레이즈부터 한다.
좌/우 손·손등/손바닥 쪽 착용·기기 축·그립·시작 변형은 프로필 키에 저장한다.
같은 기울기처럼 보여도 키가 다르면 기준을 임의 재사용하지 않는다.

### 방향을 공유해도 종목의 정자세를 공유하지 않는다

- H-UP/H-DOWN은 수평에 가까운 전완의 손바닥 위/아래라는 관측을 공유한다. 화면을 손등 쪽에
  차면 손바닥 위일 때 화면은 아래를 향하고, 손등 위일 때 화면은 위를 향한다. 안쪽 착용이면
  관계가 반대다. 좌/우·착용 면을 확인하지 않고 센서 부호를 종목에 바로 대응시키지 않는다.
- ARM-DOWN은 아래로 향한 전완의 기울기 검사만 공유한다. 덤벨 사레레와 서서 하는 기본 컬/
  해머 컬은 이 검사를 함께 쓸 후보지만, 회내/회외와 몸에 붙임까지 같은 조건으로 취급하지 않는다.
  인클라인·프리처·케이블 몸 가로지르기 변형은 기본 ARM-DOWN에 자동 편입하지 않는다.
- 랫풀·로우·벤치·숄더 프레스·삼두는 기존 반복 엔진 그룹을 유지하되 시작 방향 검사는 보류한다.
  같은 반복 엔진을 쓰는 벤치/인클라인 벤치도 랙 위치와 시작 구간의 확인 없이 하나의 준비 방향을
  강제하지 않는다. 로우의 지지 방식과 몸통 경사는 손목 기울기만으로 확정하지 않는다.
- 리버스 플라이의 손등 위는 사용자가 지정한 케이블 수행 변형의 조건이다. 뉴트럴 그립 등
  다른 수행 방식 자체를 오자세로 표시하지 않는다. 다른 변형에는 검진 보류/명시적 시작을 쓴다.

### 착용 방향에 빠진 조건

현재 `PatternWearingContext`는 사용자·좌/우 손·안/바깥 착용만 저장한다. 워치 본체의 위쪽이
팔꿈치/손 어느 쪽을 향하는지는 저장하지 않는다. 화면 UI 회전과 센서의 물리 좌표 회전은 다르므로
UI 방향을 이 값의 대용으로 쓰지 않는다. ARM-DOWN에서 팔 내림/들림을 구분하는 축의 부호를
확정하려면 본체 장착 방향 또는 사람이 확인한 축 변환 기준이 필요하다.

시작 방향 프로필에는 운동 변형·손·착용 면·본체 방향·기기·좌표계 버전·확인 기준의 출처를 묶는다.
세트 시작 때 이 조건과 프로필 버전을 고정하고 원본에 함께 남긴다. 조건이 누락되거나 도중에
바뀌면 방향 확인을 완료했다고 표시하지 않는다. 기존 3필드 착용 자료는 새 방향까지 확인한 자료로
자동 승격하지 않으며, 기존 반복 패턴의 호환성과 새 시작 방향 프로필의 호환성을 별도로 검사한다.

## 세트가 시작되는 흐름

1. 사용자가 선택한 작업 세트에 시작 요청을 보낸 뒤에만 방향 검사를 수행한다. 평소 사무 자세나
   화면을 보기 위한 손목 들기로 앱이 스스로 운동을 시작하지 않는다. 적합한 손목 방향은 특정
   운동 중이라는 증거가 아니므로, AOD 패턴만으로 세트 시작 권한을 만들지 않는다.
2. 확인한 변형·착용 조건·검증된 방향 프로필이 있는 후보는 목표 방향에 들어온 시점부터
   연속 2초를 센다. 다른 방향에서 정지하면 시간이 쌓이지 않는다. 이미 준비 방향을 잡은 채
   시작을 눌렀다면 일부러 손목을 흔들어야 검사되는 요구를 만들지 않는다.
3. 보류 종목은 운동별 정자세 확인과 일괄 2초 대기를 건너뛰고 명시적 시작으로 진행한다.
   후보라도 조건/검증 기준이 없는 경우에는 `시작 방향 미확인`과 직접 시작 경로를 제공한다.
   방향 검진이 미확인이라는 이유만으로 원래 자동 측정 가능한 운동을 수동 종목으로 바꾸지 않는다.
4. 센서 준비·표본 품질 점검과 운동별 방향 확인을 분리한다. 준비 성공으로 1회를 추가하거나,
   최초 정지 방향을 무조건 운동의 올바른 기준으로 저장하지 않는다. 첫 횟수는 선택한 판정기의
   실제 완전한 반복 경계로 결정하며 준비 시간과 판정 시작 시점을 원본에 구분해 저장한다.
5. 작업 세트에 한 번 진입하면 반복 사이 정지마다 2초 검사를 다시 요구하지 않는다. 휴식 후 새
   세트에는 다시 검사한다. 일시정지 복귀는 명시적 재개로 처리하고, 착용 조건 변경/서비스 복구로
   방향 기준이 무효가 된 경우에는 재확인 또는 미확인 시작을 쓰며 누적 횟수는 보존한다.
6. UI는 방향 조건 불일치·2초 확인 중·확인됨·조건 미확인을 구분한다. `준비 손목 방향 확인됨`은
   전체 운동 자세가 정확하다는 뜻으로 쓰지 않는다. 잘못된 방향을 유지한 시간을 성공으로
   바꾸지 않으며, 직접 시작을 누른 경우 자동 확인과 다른 출처로 기록한다.

2초는 사용자가 요청한 준비 확인 시간이다. 논문으로 최적이라고 검증된 값으로 소개하지 않는다.
목표 방향의 허용 범위·센서 갱신 품질·시작 지연은 실제 Watch8 자료로 정해야 한다.

## 구현·검증 완료 조건

1. 종목 ID만으로 `확실`을 선언하지 않는다. 지정 변형·착용 손·착용 면·기기 조건이 확인돼야 한다.
2. 애매한 종목은 자동 정자세 게이트 OFF. 필요하면 사용자의 명시적 시작 동작을 쓰며 일반 안정
   처리와 `올바른 자세 확인`을 혼동하지 않는다. 기존 준비 데이터/횟수 오탐 대책은 별도로 유지한다.
3. 고정 후보는 기대 중력 방향 영역에 들어온 뒤 안정 상태가 연속 2초 유지될 때 시작한다.
   잘못된 방향에서 2초 정지해도 시작하지 않고, 공백·착용 변경·중간 방향 이탈 시 연속 시간을 초기화한다.
4. 같은 그룹 검진기를 재사용해도 운동/착용별 확인 프로필과 기준은 분리한다. 숫자 각도·범위는
   실제 Watch8의 맞는/반대/애매한 준비 자료와 영상/사람 확인으로 확정하며 임의 값으로 성공 처리하지 않는다.
5. 손바닥 위/아래 역전, 팔 내림/팔 들림, 반대 손·안/바깥 착용, 사무 자세·손목 보기 동작,
   운동 중 정지·손잡이 바꿈을 맞는/틀린 준비 자료와 재생 검사에서 구분한다.
6. 거절·미확인 상태가 반복되면 설명 가능한 기본/수동 시작 경로를 제공한다. 이전 반복을 잃거나
   정지 동작을 새 1회로 만들지 않는다. 실제 준비 성공/잘못된 방향 거절/시작 지연을 따로 계측한다.
7. 기기 본체를 180도 돌려 찬 경우, 오래된 가속도에 새 자이로만 붙은 경우, 표본 시간 역전,
   준비 상태에서 앱/서비스 재생성, 이미 준비한 채 시작, 직접 시작 후 휴식/재개를 검사한다.
   합성 센서 검사 통과와 실제 Watch8의 방향 분리 성공은 별개로 보고한다.

## 작업 순서와 실기 승격

촬영 초기화 수정의 실기 응답을 우선 확인한다. 그다음 위 정책 분기·착용/변형 계약·방향 검진기·
명시적 시작·표시/원본 구분을 구현하고 실제 서비스 경로로 회귀 검사한다. 보류 종목에 과거의
일괄 2초 자세 게이트가 남아 있으면 완료로 보지 않는다.

초기 세 후보는 검증용 수집에서 올바른 방향, 반대 방향, 일상/손목 보기 동작을 사람이 확인해
비교한다. 기본 착용뿐 아니라 좌/우·안/바깥·본체 방향별 기준 재사용 여부도 검사한다. 검증 자료가
없는 조건에는 강제 검진을 활성화하지 않는다. 두 번째 단계에서 ARM-DOWN의 서서 하는 컬 등
공유 후보를 동일한 관측 항목으로 평가하고, 통과한 변형만 추가한다. 방향 검진 보류 33종의
세부 그립 조합 확장은 이번 작업에 섞지 않는다.
