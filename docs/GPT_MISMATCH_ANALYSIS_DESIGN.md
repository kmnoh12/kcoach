# 횟수 불일치 분석 설계 (1단계 구현, 2단계 GPT 설계)

2026-10-16. 사용자가 확정한 횟수와 워치가 센 횟수가 다를 때, 직접 구간을 찍지 않고 후보에 한 번 탭으로 답하는 흐름이다.

## 1단계: 코드로 비교 (구현·테스트 완료, 비용·전송 없음)

- `core/RepMismatch.kt`
  - `RepMismatchFinder`: 영상 반복 구간(`CameraRepProposals`)과 워치 반복 구간을 겹침 40% 이상(짧은 쪽 기준)으로 1:1 짝짓고, 짝이 없는 구간을 `VIDEO_ONLY` / `WATCH_ONLY` 후보로 낸다.
  - `VideoClockMap`: 폰 시계의 카메라 타임스탬프를 영상 재생 시간으로 보간한다. 프레임 범위를 150ms 넘게 벗어나면 추측하지 않고 null.
- 워치 구간은 원본 로그에 `PaperPeakRepAnalyzer`를 다시 돌려 얻고, `CalibrationReviewStore.alignment`의 시계 매핑으로 영상 시간에 올린다. 시계를 맞추지 못하면 후보를 내지 않고 "비교할 수 없어요"라고 보여 준다.
- 결과 화면(`CalibrationResultScreen`)은 그래프에 어긋난 구간을 붉게 칠하고, 구간마다 "이 구간에서 실제로 1회 했나요?"에 맞아요/아니에요를 받는다.
- 답은 `MismatchAnswerStore`가 캡처 폴더의 `mismatch-answers.json`에 저장한다(캡처 삭제 시 함께 삭제). **반복 라벨로 승격하지 않는다.** `CalibrationReviewStore.saveCycles`를 호출하지 않으므로 사람이 확인한 시간 정렬(alignmentReviewed)과 반복 3회 이상 조건은 그대로다.
- 기존 "반복 구간 직접 표시"(연구 모드) 버튼은 그대로 남겼다.

### 알아 둘 점
- 비교에 쓰는 워치 구간은 워치가 실시간으로 센 `WATCH_REPS`가 아니라 원본 로그의 오프라인 봉우리 분석이다. 두 값이 다르면 화면의 "워치 N회"와 후보 개수가 어긋날 수 있다.
- 후보에 한 답을 라벨로 쓰려면 기준 변경이 필요하다. 아래 "승인이 필요한 결정" 참고.

## 2단계: GPT 분석 설계 (구현 안 함, 개발 전용)

> **개발 전용이다.** 출시판에서는 ChatGPT 계정 연결을 제거하기로 했다(2026-10-16). 1단계(코드 비교)는 출시판에 그대로 들어가고, 이 2단계는 보정 데이터를 모으는 개발 단계의 도구로만 쓴다. 구현을 보류해도 출시에 영향이 없다.

### 이미지 입력 지원 여부 (확인한 것 / 못 한 것)
- 확인함: 앱의 호출 대상은 `https://api.openai.com/v1/responses`(`CHATGPT_RESOURCE`). OpenAI 공식 비전 가이드는 Responses API에서 `input_image` 콘텐츠와 base64 데이터 URL을 지원한다고 설명한다([가이드](https://developers.openai.com/docs/guides/images-vision)).
- 확인함: **현재 앱 클라이언트는 텍스트 전용**이다. `ChatGptWorkMessage`는 문자열 하나이고 `ChatGptResponseRequest.build`는 `content`를 문자열로만 만들며 옵션 키를 `model/reasoning/store/stream`으로 제한한다. 이미지를 보내려면 content 배열(`input_text` + `input_image`) 지원과 크기 제한 검증을 추가해야 한다. `ChatGptModels`도 모델별 입력 종류 메타데이터를 읽지 않는다(이름으로 추론하지 않는 규칙).
- **못 함**: ChatGPT 계정 OAuth 토큰(구독 한도 공유)으로 이 엔드포인트에 이미지를 실제로 보냈을 때 허용되는지, 어떤 모델이 이미지를 받는지는 폰에서 실제 호출해 봐야 안다. 이미지 크기·장수 한도도 OpenAI 원문에서 확인하지 못했다. 미확인이다.

### 보내는 것: 두 모드 비교
| | 골격 그림만 (권장 기본값) | 원본 프레임 |
|---|---|---|
| 내용 | MediaPipe 관절 좌표로 그린 선 그림 + 시계열 | 후보 구간의 핵심 프레임 몇 장 |
| 프라이버시 | 얼굴·방·몸 외형이 나가지 않음 | 얼굴·집 내부가 나갈 수 있음 |
| 정보량 | 관절 위치만. 가려짐·기구 모양은 모름 | 기구, 가려짐, 다른 사람 등 맥락 포함 |
| 성능 | **검증 전** | **검증 전** |
| 토큰 비용 | 낮음(좌표를 숫자로도 보낼 수 있음) | 이미지 토큰 추가 |

기본값은 골격 그림 + 숫자 시계열로 하고, 원본 프레임은 사용자가 건건이 직접 켜는 옵션으로 둔다. 골격만으로 성능이 부족하면 그때 비교한다. 이미 있는 `AiCalibrationInput`(숫자 JSON)과 `AiCalibrationController` 경로, 프롬프트는 `ai-coach/*.prompt.md` 자산 방식을 재사용한다. 새 프롬프트 `mismatch-analysis`는 "어긋난 이유와 구간 후보"만 요구하고 횟수 판단을 요구하지 않는다.

### 호출 조건
1단계가 후보를 못 냈거나 사용자가 "그래도 안 맞아요"를 누를 때만 제안한다. 자동 호출하지 않는다.

### 동의 창 (전송 건건이)
- 매번 묻는다. "이번에 한 번만" 외에 "항상 허용"은 두지 않는다.
- 문구에 반드시 포함: 무엇을(골격 그림·관절 좌표·워치 신호 / 원본 프레임 N장), 어디로(OpenAI, 사용자 본인 ChatGPT 계정), 몇 건인지, 앱 개발사 서버에는 저장하지 않고 이 기기에만 저장한다는 점. 전송한 뒤 OpenAI 쪽 보관은 앱이 통제하지 않는다. `store=false`를 요청에 넣지만 OpenAI의 실제 보관 정책은 확인 필요.
- 거절하면 1단계와 직접 표시 흐름이 그대로 동작한다. 전송 전에는 아무것도 만들지 않는다.
- 법적 고지 필요 여부는 `DATA_STORAGE_DESIGN.md`의 확인 필요 항목에서 다룬다.

### 출력 처리
- GPT 출력은 제안일 뿐이다. 구간 후보로만 화면에 올리고, 사용자가 맞아요를 눌러야 1단계와 같은 `mismatch-answers.json`에 기록된다.
- GPT가 센 횟수는 쓰지 않는다. 응답에서 횟수 필드를 아예 요구하지 않고, 있어도 버린다.
- `GPT의 확신만으로 활성화하지 않는다`(`GPT_CALIBRATION_WORKER_HANDOFF.md`)를 유지한다.

## 승인이 필요한 결정 (사용자 확인 전 구현 금지)
1. 불일치 후보에 대한 사용자 답을 반복 라벨로 승격할지. 승격하려면 `CalibrationReviewStore`의 두 조건(사람이 확인한 시간 정렬, 확인된 반복 3회 이상)을 어떻게 충족시킬지 정해야 한다. 지금은 승격하지 않는다.
2. 이미지 입력을 위한 `ChatGptResponses` 확장과 실제 호출 시험(폰, 사용자 계정, 영상 전송 발생).
3. 기본 모드를 골격 그림으로 할지.
