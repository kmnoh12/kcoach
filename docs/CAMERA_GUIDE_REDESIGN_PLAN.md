# 측정·보정 카메라 화면 개편 + 졸라맨 자세 가이드 계획

작성일: 2026-10-15 · 기준: 폰 0.7.8 (POSE_INIT 해결 후 실기기에서 골격 표시 확인)
상태: 계획. 코드 수정 전.

## 1. 왜 바꾸나 (사용자 실기 피드백)

- 카메라 화면이 앱 디자인과 따로 논다. `CalibrationCameraActivity`만 옛 View 시스템
  (`LinearLayout`, 기본 `Button`·`CheckBox`·`Spinner`)으로 짜여 있고, 앱 표준
  `KColors`·`KShapes.Control`(6dp)·Compose 컴포넌트를 쓰지 않는다.
- 미리보기가 검은 여백 속 사각형(`FIT_CENTER`)으로 떠 있고, 그 위아래로 버튼이 쌓여 있다.
- 상단 설명이 5~6줄로 너무 길고, 실제로 도움이 안 된다. 종목별 안내는 한두 줄이면 충분하고,
  자세는 글이 아니라 그림으로 보여 줘야 한다.
- 제목이 상태 표시줄 아래로 파고든다(인셋 미처리). 스크린샷에서 "카메라"와 제목이 겹친다.
- 골격에 관절 점이 없어서 팔꿈치·손목이 잘 안 읽힌다.
- 시작 자세를 미리 보여 주지 않아서 사용자가 무엇을 따라 해야 하는지 모른다.
- 상반신만 찍으면 컬·로우·푸시다운도 실패한다. 이 버그는 코드에서 확인했다(§4).

## 2. 확정된 방향 (대화에서 합의)

- 가이드 그림은 **신호등 졸라맨**으로 한다. 얼굴이 없고, 머리는 몸통과 떨어진 원이며,
  둥근 팔다리를 가진 단색 반투명 실루엣이다. 곤약인간(얼굴 구멍)은 징그러워서 제외했다.
- 블렌더나 three.js는 쓰지 않는다. 기존 Canvas overlay에 2D로 그린다.
- 졸라맨은 화면에 고정하지 않는다. **매 프레임 사용자 관절을 따라가며** 위치와 크기를 맞춘다.
- 졸라맨과 사용자 관절이 겹치는지는 판정하지 않는다. 판정은 기존 관절 각도 판정
  (`poseReady`)을 그대로 쓴다. 각도가 통과하면 초록으로 바뀌고 체크가 떴다가 가이드가 사라진다.
- 상체 종목은 상체만 보여도 통과한다. 졸라맨도 상체만 그린다.
- 종목별로 촬영 방향을 지킨다. 예를 들어 덤벨 컬은 측면이나 사선이다.
  시안은 `work/overlay-mockups/overlay-follow-demo-side.png`다.

## 3. 새 화면 구성

- 전체 화면 카메라 미리보기를 쓴다(`FILL_CENTER`, 상태 표시줄·내비게이션 인셋 처리).
  관절·졸라맨 좌표 변환은 잘린 영역 기준으로 다시 계산한다.
- 상단에는 반투명 바를 둔다. 종목명 한 줄과 안내 한두 줄(§5)만 넣는다.
- 하단에는 시트를 둔다. 상태 문구 한 줄과 주 버튼 하나("워치와 함께 촬영 시작"/"종료·저장")를 둔다.
- 워치 착용 손, 화면 방향, 시작 방향 조건, "시작 자세 확인" 체크는 촬영 전 설정 시트로 옮긴다.
  매번 다시 묻지 않도록, 착용 손·화면 방향의 기본값은 Codex2가 만들고 있는 착용 설정 저장소
  (`WorkoutWearingStore`)에서 읽는다. 별도 저장소를 새로 만들지 않는다. 기존 저장 계약
  (`StartWristContext`, wearing, `startReviewed` 요구)은 그대로 유지한다.
  이 단계는 Codex2 변경이 main에 커밋된 뒤 이 브랜치를 그 위로 올리고 진행한다.
- "저장한 촬영 확인"은 상단 바의 아이콘으로 옮긴다.
- "오류 정보 복사"는 실패할 때만 하단 시트에 나타나게 한다(지금 동작 유지).
- 색은 `KColors`(Bg, Surface, Accent 민트, Muted), 모서리는 `KShapes.Control` 6dp,
  패널은 `KShapes.Panel`, 시트는 `KShapes.Sheet`를 쓴다.
  Activity UI를 Compose로 옮기고, CameraX `PreviewView`는 `AndroidView`로 감싼다.

## 4. 필수 관절 수정 (확인된 버그)

`core/.../CameraCaptureGuide.kt`의 `required`에는 기본값으로 `shoulder, elbow, wrist, hip`이 들어 있다.
그런데 `ELBOW_FOLD`·`ELBOW_PRESS` 각도는 어깨-팔꿈치-손목만 쓴다(`UpperBodyPoseCounter.metric`).
그래서 셀카로 상반신만 찍어 골반이 화면 밖에 있으면 `visible()`이 false가 되어 실패한다.

- 컬·로우·랫풀다운·프레스·푸시다운 계열(팔꿈치 각도 지표)의 필수 관절에서 골반을 뺀다.
- 레터럴 레이즈(`SHOULDER_RAISE`)는 팔-몸통 각도에 골반이 필요하므로 유지한다.
- 스쿼트·하체 MANUAL 종목은 지금처럼 전신이나 하체를 요구한다.
- `CameraCaptureGuideTest`에 "골반이 화면 밖이어도 컬 시작 자세가 통과한다"는 테스트를 추가한다.

## 5. 종목별 안내 문구 (한두 줄)

지금 안내는 방향 + 프레이밍 + 시작 설명 + 면책 문구를 이어 붙여 5~6줄이 된다. 형식을 다음으로 바꾼다.

- 1줄: `{촬영 방향} · {보여야 하는 범위}` 예) `왼쪽 측면 · 상체와 왼팔이 보이게`
- 2줄(필요할 때만): 시작 자세 한 구절. 예) `팔을 쭉 내린 상태에서 시작`

면책 문구("관측 범위 밖 자세는 평가하지 않아요" 등)와 셀카 반전 설명은 화면에서 빼고 도움말로 옮긴다.
43개 종목 문구는 `ReviewedMeasurementContracts`의 recipe에서 만들어 내고, 필요한 종목만 따로 지정한다.

## 6. 졸라맨 가이드 스펙

### 자세 유형 9가지 (43개 종목 매핑)

| 유형 | 방향 | 대표 종목 |
|---|---|---|
| 서서 · 팔 내림 | 측면/사선 | 덤벨·바벨·EZ 컬, 해머 컬 |
| 서서 · 팔 내림 | 정면 | 레터럴 레이즈 |
| 서서 · 팔꿈치 굽힘 | 측면 | 케이블 푸시다운, 익스터널 로테이션 |
| 앉아서 · 팔 위로 | 후면 사선 | 랫풀다운 계열 |
| 앉아서 · 손 어깨 높이 | 정면/사선 | 숄더 프레스 계열 |
| 앉아서 · 팔 앞으로 | 측면 | 시티드 로우, 체스트 프레스, 플라이 |
| 숙여서 · 팔 내림 | 측면 | 바벨 로우, 원암 로우, T바 로우 |
| 누워서 · 팔 위로 | 측면 | 벤치 프레스, 라잉 익스텐션 |
| 서서 · 전신 | 측면 | 스쿼트 |

인클라인 컬·프리처 컬·풀오버·오버헤드 익스텐션·하체 MANUAL 종목은 구현할 때 가장 가까운
유형에 넣거나 따로 정의한다. 유형별 목표 각도는 기존 `CameraMotion.atRest` 기준을 따른다.

### 따라가기 규칙

- 기준점: 정면 유형은 양 어깨 중심, 측면·사선 유형은 **워치 쪽 어깨**를 쓴다.
- 크기 기준: 정면 유형은 어깨 폭, 측면·사선 유형은 **위팔 길이**(어깨–팔꿈치)를 쓴다.
  측면에서는 어깨 폭이 거의 0이 되어 쓸 수 없다.
- 비율: 사용자의 관절이 보이면 실제 분절 길이를 쓰고, 안 보이면 표준 인체 비율
  (Drillis–Contini, 키 대비 위팔 0.186·아래팔 0.146·어깨 폭 0.259·몸통 0.288)로 채운다.
- 자세: 사용자의 실제 기준점에서 출발해 목표 각도로 그린다. 판정 대상 팔은 진하게,
  뒤쪽 팔다리는 옅게 그린다. 몸통과 겹치는 팔은 어두운 테두리로 구분한다.
- 상체 유형은 하체를 그리지 않고, 화면 아래 가장자리에서 페이드 처리한다.
- 떨림을 줄이려고 위치와 크기에 짧은 지수 평활을 적용한다. 기준점을 놓치면 마지막 위치에서 서서히 흐려지게 한다.
- 상태: 회색 반투명(대기) → 초록 반투명 + 체크(`poseReady`) → 약 0.6초 뒤 가이드 페이드아웃.
  자세가 무너지면 다시 회색으로 나타난다(촬영 중에는 표시하지 않는다).

### 사용자 관절 표시

- 선은 민트(`KColors.Accent`) 약 65% 불투명도로 그린다.
- 관절은 흰 점에 민트 테두리를 두른다.
- 신뢰도가 낮은 관절은 숨기지 않고 작고 흐리게 그린다.

## 7. 구현 순서

1. (완료, 브랜치 `claude/camera-guide`) 필수 관절 수정과 테스트(§4).
2. (완료) 관절 점 스타일(§6 사용자 관절 표시)을 기존 `PoseOverlay`에 반영했다.
3. (완료, 실기기 미확인) 졸라맨 모델은 `core/.../CameraPoseGuide.kt`에 만들었다(자세 유형 17개, 따라가기·평활).
   overlay에서 사용자 골격 뒤에 그리고, `poseReady`면 초록과 체크를 보여 준 뒤 0.6초 후 페이드아웃한다.
   하체 MANUAL 종목 7개는 가이드 없이 둔다.
4. 카메라 화면을 Compose로 개편한다(§3). 안내 문구 생성(§5)과 설정 시트를 만든다.
5. 디버그 빌드로 확인한다. 빌드가 끝나면 Gradle 데몬을 종료한다(8GB 메모리 부담 때문).
6. 사용자 실기기에서 덤벨 컬 측면, 상반신만 보이는 셀카, 사선, 멀리 서기를 확인한다.

## 8. 완료 판정

- 실제 폰에서 덤벨 컬을 측면·상반신만 보이게 찍었을 때 졸라맨이 따라오고, 시작 자세에서 초록이 되고, 촬영이 시작되는지 확인한다.
- 다른 자세 유형도 최소 1종목씩 실기기에서 확인한다.
- 시안과 정적 검사만으로는 완료로 보지 않는다.
