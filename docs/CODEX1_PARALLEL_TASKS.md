# 코덱스1 후순위 병행 작업 경계

2026-10-15. 원래 전체 목표의 최종 통합·검사·릴리스는 코덱스2가 맡는다.
사용자가 원래 작업과 병행 작업을 모두 끝낸 뒤 공개하도록 재확인했다.
이미 연결된 기능은 GPT_IMPLEMENTATION_STATUS.md와 현재 코드로 확인하고 재구현하지 않는다.

## 작업 1 — 선택적 실시간 템포 피드백의 공통 판정기

MEASUREMENT_REDESIGN_PLAN.md 8절의 남은 선택적 피드백을 위한 독립 모듈이다.
현재 관측 시간/각속도 결과는 이미 구현돼 있으므로 다시 만들지 않는다.

- 새 core 클래스 TempoFeedbackPolicy.kt 및 전용 테스트로 한정한다.
- 입력은 확인된 반복/위상 시간, 사용자가 정한 목표 범위, 측정 품질, 세트/시도 식별자다.
- 유효한 위상이 없으면 수축/이완 시간을 추정하거나 전체 시간을 반으로 나누지 않는다.
- 목표 범위 이탈의 지속 조건과 알림 간격 제한을 명시적인 설정으로 받는다.
- 품질 부족/부분 반복/중복·역행 이벤트에서는 새 알림을 만들지 않는다.
- 세트/시도 변경과 일시정지 후 연속 조건을 초기화하며 기능 OFF는 기본값이다.
- 판단 결과는 관측된 템포와 근거만 반환한다. 자세 정확도·근육 피로·RIR 판정은 하지 않는다.
- 워치 서비스/진동/UI/동기화 연결은 코덱스2가 통합한다. 적용 전 성능 개선을 주장하지 않는다.
- 테스트는 고립된 구현 복제가 아니라 중복 이벤트·시도 전환·품질 이탈·빈도 제한의 공개 동작을 확인한다.

## 작업 2 — 실제 측정 ZIP 검사 도구의 품질 보고 보강

tools/inspect_measurement_export.py와 tools/test_inspect_measurement_export.py만 수정한다.
기존 SHA/시도 식별/실제 0회 구분은 재구현하지 않는다.

- 원본 가속도와 자이로 결합 나이, 미래/누락 가속도, 두 센서의 정확도 미확인·불량을 별도로 보고한다.
- 구형 KCS v1의 누락 메타데이터를 정상 품질이나 실제 0으로 채우지 않는다.
- 기존 앱 내보내기 형식·필수 파일·원본은 바꾸지 않는다.
- 짧은 합성 ZIP으로 경계·손상 사례를 검사한다. 합성 검사를 Watch8 정확도 증거로 표시하지 않는다.
- 검사 결과는 검증 가능 여부와 부족한 근거를 설명하며 엔진을 자동 승인하지 않는다.

## 작업 3 — 병행 완료된 AI 경로의 예외·경쟁 검증과 재현된 결함 수정

이미 구현된 상담/종료 리뷰/요약을 다시 만들지 않는다.
폰의 AiCoach*, AutomaticWorkoutReview, WorkoutReview* 영역과 그 전용 테스트를 대상으로 한다.

- 요청 중 계정 변경/로그아웃/기능 OFF, 취소/시간 초과 뒤 늦게 도착한 응답.
- 종료 이벤트 중복 수신·앱 재생성 시 동일 리뷰 중복 실행 여부.
- 모델이 도구를 여러 번 호출할 때 소유권·최대 라운드/호출 수 유지 여부.
- 리뷰/요약 생성 중 수동 기록·센서 분석 revision이 바뀌었을 때 오래된 근거를 현재 결과로 저장하는지.
- 거짓 transport로 실제 controller/store 흐름을 재현한다. 실제 계정 한도 소모는 이 작업의 대상이 아니다.
- 결함이 재현되면 해당 소유 영역에서만 수정한다. 재현하지 못한 가정으로 구조를 바꾸지 않는다.

## 공통 실행·병합 규칙

- 별도 worktree/브랜치의 현재 커밋 기준으로 작업하고 진행 중 원래 변경은 옮기거나 덮지 않는다.
- 코덱스2 소유: StartWrist*, StartDirection*, ReviewedStartWristDirection*, StartPoseStabilityGate,
  CalibrationCameraActivity, CalibrationCaptureStore, CalibrationReviewActivity, CaptureClockStore,
  WorkoutWearingStore, WearWorkoutService, WearCommandService, WearSync, manifest, 공통 화면/설정 진입.
- 공통 파일 연결이 필요하면 변경 위치와 계약을 인계한다. 해당 연결은 최종 통합에서 코덱스2가 한다.
- 중간에는 대상 클래스 --tests 또는 해당 Python 테스트만 실행한다.
- 전체 모듈 테스트/lint/OTA 빌드/reviews JSON 생성은 반복하지 않는다.
- 버전 상승/공개 배포/latest manifest 변경은 하지 않는다. 임시 공개된 0.7.6/0.2.6 코드는 재사용하지 않는다.
- 완료 시 변경 파일, 전용 테스트 결과, 통합할 API/위치, 실제 미확인 범위를 인계한다.
- 구현된 파일만 명시적으로 커밋하며 다른 계정의 진행 중 변경을 함께 커밋하지 않는다.
- 두 계정 변경의 병합과 최종 전체 검사/OTA/릴리스는 코덱스2가 한 번에 진행한다.
