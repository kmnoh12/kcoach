# 코덱스2 중심 3에이전트 운영안 — 2026-10-15

사용자의 목표 계속 지시와 실제 active 상태 확인으로 개발을 재개한다.
이 문서는 최근 코덱스1 대화와 클로드 인계를 대조한 운영 계획이다.
실제 워커 실행/종료는 work의 턴별 로그와 최종 보고로 별도 기록한다.

총 3명은 코덱스2 본인과 CLI 워커 2명이다. 여기에 별도 하위 에이전트를 중첩해서 늘리지 않는다.
사용자는 이 앱에서만 지시하고 코덱스2가 두 워커에 배정·결과 확인·충돌 조율을 한다.
코덱스1이 한때 자신을 총괄로 적은 제안은 최신 대화에서 명시적으로 정정됐다.

## 기존 작업 보존과 소유권

1. 재개 시 main의 미커밋 폰 결과 진입 변경과 각 작업 폴더 상태부터 확인한다. 다른 담당의
   변경은 삭제하거나 덮어쓰지 않는다. 기존 완료 항목은 최신 소스와 인계로 대조해 재작업하지 않는다.
2. MainActivity.kt, AndroidManifest.xml, 빌드/버전/릴리스 파일의 통합 수정은 코덱스2가 맡는다.
   UI 워커는 화면 컴포넌트와 필요한 연결 계약을 제출한다. 통신 워커가 MainActivity 연결이 필요하면
   의도·함수·인자와 패치를 인계해 동시에 같은 파일을 편집하지 않는다.
3. core는 모듈 전체를 한 명이 독점하지 않는다. 센서/엔진과 카메라가 함께 쓰므로 배정 전에
   정확한 파일 목록을 잠근다. 공통 저장 형식·wire 변경은 코덱스2가 계약을 확정한 뒤 한 명만 수정한다.
4. 워커는 자신에게 지정된 worktree와 브랜치만 수정한다. main을 직접 fast-forward하거나
   버전을 올리거나 공개하지 않는다. 코덱스2가 검토 후 순서대로 병합한다.
5. 한 세션을 앱과 CLI에서 동시에 실행하지 않는다. 코덱스1은 기존 세션 인계 후
   해당 CODEX_HOME의 resume을 사용한다. 클로드는 긴 데스크톱 세션을 재개하지 않고,
   최신 인계와 한정된 작업 설명으로 새 claude -p 세션을 사용한다.

## 재개 후 첫 배정

- 코덱스2: 현재 미커밋 결과 진입 묶음 정리, 잔여 목록 고정, 폰 측 데이터/화면 연결 계약 제공.
- 코덱스1: 최신 사용자 합의를 반영한 D2 실제 워치 적용, 대기/최근 정보, 완료의 폰에서 보기 연결.
  결과 열기는 PHONE_RESULT_NAVIGATION_HANDOFF.md의 정확한 완료 ID VIEW URI를 따른다.
  예전 e25063c를 최종 시안으로 바로 병합하지 않는다.
- 클로드: 이미 main에 있는 카메라 1~4단계를 재구현하지 않는다. 최신 잔여 UI/카메라 문제를
  좁혀 배정한다. 실기 자료가 없는 졸라맨 품질을 임의 임계값 재조정으로 완료 처리하지 않는다.

새 지시는 목록에 추가하되 현재 묶음의 완료 조건을 무한히 늘리지 않는다. 우선순위를 바꾸면
기존 작업의 보류 사유와 다음 순서를 짧게 기록한다. 할 일이 없으면 새 일을 만들어 반복하지 않는다.

## 워커 요청과 완료 보고

사용자 추가 지시: 코덱스2는 자기 구현을 진행하면서 두 CLI의 응답 턴이 끝날 때마다
완료 내용·검사 결과·남은 문제·통합 상태를 확인하고 사용자에게 짧게 보고한다.
완료 보고가 왔다는 이유만으로 구현/병합/배포/실기 확인을 같은 상태로 표시하지 않는다.
보고 예: `코덱스1: 완료 화면 구현·대상 검사 통과, 미병합. 클로드: 자동 촬영 안내 정리,
실기 미확인. 나: 폰 결과 연결 진행 중.` 실패·입력 필요는 발견 즉시 보고한다.

요청에는 목표·정확한 소유 파일·수정 금지 파일·최신 기준 커밋·완료 조건·실행할 대상 검사만 넣는다.
워커 보고는 변경 파일/커밋, 검사 명령과 결과, 미확인·막힌 사항으로 제한한다.
코덱스2는 요약만 믿지 않고 diff와 검사 로그를 확인하되 동일 검사를 이유 없이 다시 실행하지 않는다.
코덱스2는 워커가 진행하는 동안 독립된 자기 작업을 한다. 상태 조회와 인계 문서 재작성만 반복하지 않는다.

## 검사와 자원 사용

중간에는 수정한 로직의 대상 테스트만 묶어서 실행한다. 단순 색상·문구 변경에 새 픽셀 검사
기반을 만들지 않는다. 새 실패나 코드 변경이 없는 재실행은 하지 않는다.
여러 JVM/Gradle이 메모리를 경쟁하지 않도록 무거운 검사는 겹치지 않게 조율한다.
클로드는 --no-daemon을 쓰고, 누구도 gradle --stop으로 다른 작업의 데몬을 끄지 않는다.
모든 구현·병합 후 tools/release.sh를 통한 전체 테스트/lint/OTA를 한 번 실행한다.
실패하면 원인 수정과 해당 대상만 보완하며, 새 영향이 없는 전체 검사를 다시 시작하지 않는다.
중간 reviews/*.json을 반복 생성하지 않는다.

## 진행률과 완료 판정

현재 전체 작업량은 약 85%, 구현만 약 90~95%로 추정한다. 자동 산출된 진척도나 측정 정확도가 아니다.
워치 최종 화면/기기 간 결과 열기, 신규 UI 통합, 마지막 검사·새 배포와 실제 계정/Watch8 확인이 남았다.
실측 정확도 개선과 개인 보정 효과는 아직 통과하지 않았다.
소프트웨어 업데이트 제공과 실측 성능 승격은 별도로 보고한다. 이미 허용된 사용자 업데이트→사용 후
문제 보고 흐름을 유지하며, 실측 자료 부재 때문에 가능한 구현·배포까지 무기한 묶어두지 않는다.
반대로 APK 배포만으로 전체 성능 목표를 완료 처리하지 않는다.
