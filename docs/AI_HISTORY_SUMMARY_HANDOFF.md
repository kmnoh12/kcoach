사용자는 한도로 중지된 코덱스2의 촬영·시작 방향 작업을 그대로 재개하도록 두고,

촬영 엔진, 시작 방향, 워치 운동 화면과 업데이트 제어는 이 작업에서 변경하지 않았다.

## 구현된 것

- `WorkoutComparison`: 동일 routineId의 직전 완료 세션을 sessionId/startedAtMs로 구분한다.
  이름 변경과 같은 날 여러 운동을 처리하고 동일 시각의 모호한 순서는 추정하지 않는다.
  일반 세트만 비교하며 운동·기구·그립·변형 변경, 누락 조건, 추가/삭제 조건을 표시한다.
  같은 중량의 반복 변화와 같은 반복 조건의 중량 목록을 계산하며 세트 추가는 별도 표시한다.
  미측정 횟수/중량과 0회는 구분한다.
- `FinishedWorkoutStore.evidenceForSessions` / `AiCoachHistoryReader`: 연결된 계정 소유 기록 전체에서
  기준을 찾는다. 최근 100회 또는 다른 계정의 최근 기록 때문에 기준을 잃지 않는다.
  늦은 분석이 저장 기록에 아직 반영되지 않았을 때 기존 reducer로 읽기 결과를 보정하되,
  수동 횟수와 원본 저장 파일은 바꾸지 않는다.
- `AiCoachSummaryStore`: 전체 연결 기록의 세션 수·일반/웜업 세트·반복/훈련량·누락 수·최근 조건별
  추세를 계산해 재생성 가능한 캐시로 저장한다. 모델의 조언이나 추정 개인정보를 사실로 저장하지 않는다.
  프로필 revision, 기록 내용, 연결 기록, 실제 분석 revision이 바뀌면 다음 조회에서 갱신한다.
  요약에는 원본 입력 해시, 캐시에는 각 세션의 원본 revision을 보존한다.
- `AiCoachContextBuilder`: 위 비교와 요약을 기존 상담 요청 데이터에 연결한다.
  관련 기록의 직전 기준도 요청에 포함하고, 60,000자 제한과 생략 표시를 유지한다.
  센서 제안 횟수는 `phone_record_proposal`로 구분하며 혼합 신호의 속도/ROM 오해 필드는 전달하지 않는다.

`workout_review` 모델 호출·결과 화면, GPT 개인 보정, 장기 모델 해석 요약은 별도 후속 범위다.
이번 비교 계산기는 그 경로에서도 재사용할 수 있다. 실제 계정 호출과 실제 기기 운동 정확도는 검증하지 않았다.
앱 버전과 공개 APK는 바꾸지 않았다.
