# 측정·보정 카메라 재검토 (2026-10-17)

## 방향 판정과 근거

준비 판정은 팔꿈치 각도와 관절 가시성만 보던 것이 원인이다. 이제 `CameraOrientationPolicy`가 운동별 목표를 소유하고 `CameraCaptureGuide.diagnose`의 동일한 판정으로 시작 허용·녹색·안내 문구를 결정한다. 몸통의 양어깨(11·12)와 양골반(23·24)의 세계좌표 x/z 양측 축으로 부호 있는 요 각도를 구한다. 정면 0°, 측면 90°, 후면 180°이며 해부학적 왼쪽이 가까우면 음수다. 양측 축의 차이가 25°를 넘는 몸통 비틀림, 짧아진 축, 낮은 신뢰도는 거절한다. 셀카 미리보기 반전으로 해부학적 좌우를 바꾸지 않는다.

최근 9프레임 중간값, 최소 5프레임, 진입 ±12°와 이탈 ±15°를 쓴다. ±12°는 45°의 정면/측면과 각각 33° 이상 떨어지도록 잡은 준비용 보수적 허용치이며, 3°는 경계 깜빡임 억제 여유다. MediaPipe의 각도 오차가 ±12°라는 실험 근거는 없다. 실제 폰과 운동별 검증 전까지 잠정값이다. 현재 프레임의 명백한 이탈·팔 가림·사람 누락은 중간값이 좋아도 즉시 거절하고, 누락/500ms 초과 간격은 이력을 비운다. 팔꿈치·손목의 가시성과 몸통 투영 안쪽/뒤쪽 깊이를 함께 검사한다. 기구의 실제 가림은 랜드마크의 신뢰도·위치로만 추정한다.

좌표와 관절 번호는 [MediaPipe Pose Landmarker 공식 안내](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)를 따른다. 신경망이 추정한 3D 좌표는 물리적 자세 센서나 개인 식별자가 아니며, 이 방식의 실제 요 각도 정확도를 확인한 것은 아니다.

## 보정 안전 경로

촬영 원본 → 사용자 총횟수/별도 반복 경계 확인 → `PatternCandidateStore.readSet` 품질 검사 → 후보 → 원본 재검사 → 전체 비교 가능한 촬영의 generic 대 causal DTW 재생 → 기존 독립 폰·실제 워치·고정 회귀 검증 → ACTIVATE/STAGED → 다음 시도 실제 사용/APPLIED 순서다. 총횟수 확인은 반복 경계의 학습 허가가 아니다.

품질 비율은 원시 요가 목표 ±12° 안인 프레임만 세어 녹색의 이탈 여유 ±15°보다 보수적으로 계산한다. 품질 문턱은 방향 유효 프레임 ≥90%, 필수 관절 가시 프레임 ≥95%, 30프레임 이상, 확인 반복 ≥8회, 카메라·워치·사용자 횟수 일치다. 카메라 횟수를 관측할 수 없는 운동은 거절한다. 후보 생성/채택/복원/대기 중인 활성화 재시도마다 원본으로 재확인한다. 실패해도 사용자의 영상·센서·횟수 답은 보관한다.

회귀 비교는 평균과 운동별 합계 외에 **각 촬영에서** 기존 모델과 generic보다 횟수 오차가 증가하면 실패한다. causal 출력도 같은 조건을 적용한다. 기존 20세트·3일·150회 및 독립 검증/엄격한 개선 기준은 완화하지 않았다. 학습 촬영 재생은 회귀 검사이며 독립 정확도 증거가 아니다. 신규 증거에는 `safetyVersion=1`; 없는 예전 활성/대기 영수증은 워치에서 generic으로 격리하고 DISABLE은 허용한다. 근거 없는 구형 개인 임계값 모델은 새 시도에서 자동 적용하지 않는다. 이미 진행 중인 시도의 기존 snapshot은 유지한다.

확인 횟수 저장/워치 원본 도착/연구 모드 경계 수정 때 활성 모델 원본이 무효이거나 확인된 재생 오차가 generic보다 크면 정확한 모델의 DISABLE을 자동 대기열에 넣는다. 실제 해제는 다음 시도의 generic 샘플 처리와 `confirmDisabled` ACK 이후다. 전송 요청 성공을 실제 해제 성공이라고 보고하지 않는다. 판정할 실제 총횟수가 없으면 실시간 generic과 개인 카운트가 다르다는 이유만으로 누가 맞는지 추정하지 않는다.

워치 카메라 상태는 별도 versioned 경로에 session/set/attempt/revision을 묶어 보낸다. `phoneCameraRecording`과 `calibrationConfirmedReps`는 상태 방송으로 전달하며, STOP 후에도 센서 횟수와 확인 횟수를 분리해 보존한다. 오래된 true/다른 시도의 확인값은 무시한다. 보정의 기존 calibration 접두사 제외 규칙으로 일반 운동 합계·기록·과부하로 유입되지 않는다. 기록 갱신 전달 코드는 수정하지 않았다.

## 검증 범위

합성 랜드마크의 정면/45°/90°/반대 회전/후면/가림/프레임 공백/히스테리시스/녹색-문구 일치, 품질 미달 제외, 올바른 합성 패턴의 비교 통과, 악화 패턴 차단 및 기존 활성화/해제 영수증 경로를 검사한다. Robolectric의 영상은 MediaExtractor fixture이며 실제 카메라나 재생 검증이 아니다.

이 worktree에는 `work/datasets`가 없어서 원본 프로젝트 `../워치짐/work/datasets/mmfit-probe`를 읽기 전용으로 사용했다. 기존 `CurrentDetectorReplay`의 실제 샘플 시각/가장 최근 가속도 결합 방식을 재사용했고 보간하거나 미래 정지 샘플을 추가하지 않았다. [MM-Fit](https://mmfit.github.io/) w00 숄더프레스 3세트에서 라벨 10/10/9회, generic 9/7/6회, 고의로 나쁜 합성 DTW 0/0/0회를 얻었고 회귀 문턱이 차단했다. 교대 컬의 양팔 총횟수는 한 손목 정답으로 쓰지 않았다.

이는 공개 타 기기 자료에 대한 차단 장치 stress test다. 실제 사용자/Watch8/손목 착용에 맞는 개인 패턴 검증으로 혼용하지 않으며 앱의 채택 증거로 주입하지 않는다. 실제 보정 촬영과 네이티브 실측 출력이 없으므로 개인 보정이 실제 정확도를 올린다는 근거는 아직 부족하다. 임의 사용자·미래 세트에서 정확도가 절대로 떨어지지 않는다는 보장도 할 수 없다. 근거가 모자라면 일반 검출기를 유지하는 구현이다.
