# KCoach 리부트 플랜 (2026-10-11)

## 목표

손등 위 Galaxy Watch8 하나로 위 리모컨처럼 손목 움직임을 3D로 보여주고, 반복수·속도·반복 간 차이를 알려주는 개인 트레이너 앱.
워치는 센서 신호를 보내고 받기만 한다. 계산과 분석은 폰이 한다.

## 원칙

- 살리는 것: `core` 알고리즘(반복 감지, 보정 프로필, 운동 카탈로그)과 GitHub 업데이트.
- 새로 짜는 것: 폰·워치 화면, 센서 수집, 폰↔워치 연결.
- 숫자로 확인하기 전에는 측정 방식을 확정하지 않는다.
- 배포는 항상 `tools/release.sh`. ADB는 쓰지 않는다.

## 단계

### 0단계: 인터넷 업데이트 — 완료

GitHub Releases로 전환. 폰 0.5.12, 워치 0.1.26 설치 완료. 실제 GitHub 경유 업데이트는 1단계 배포가 첫 실전.

### 1단계: 실측 프로브

기존 앱에 "실측 모드" 화면을 추가해 업데이트로 배포한다.

| 재는 것 | 방법 | 합격 기준 |
|---|---|---|
| 센서 속도 | 워치 화면 켜짐/꺼짐에서 가속도·자이로 실제 Hz | 세트 중 50Hz 이상 유지 |
| 폰 전송 | 워치→폰 실시간 스트림의 지연·누락 | 지연 0.5초 이하, 누락 1% 이하 |
| 3D 궤적 | 반복 상·하단 정지점마다 0점 리셋한 손목 궤적을 폰 3D 화면에 표시 | 같은 동작 반복이 눈으로 비슷한 모양 |
| 업데이트 속도 | 압축 빌드로 워치 APK 크기 줄이기 | 6MB 이하, 다운로드 1분 이내 |

테스트 운동: 덤벨 컬, 랫풀다운, 체스트프레스 (손목 움직임이 큰 것부터).

### 2단계: 측정 방식 확정

1단계 숫자를 보고 결정한다.
- 반복 카운트: 기존 `core` 상태 머신으로 시작하고, 실제 세트 데이터에 실제 횟수를 붙여 모은다. 데이터가 쌓이면 폰에서 학습 모델로 교체를 검토한다.
- 3D 궤적: 1단계 결과가 좋으면 정식 기능, 아니면 손목 각도·회전만 표시.

### 3단계: 새 구조

- 워치: 센서 수집 + 로컬 저장 + 폰으로 스트림. 화면은 최소(세트, 횟수, 휴식, 심박).
- 폰: 세션 진행, 분석, 기록, 3D 표시.
- 연결: 실시간 스트림, 끊기면 워치에 저장했다가 다시 붙으면 이어서 전송.
- 폰 4,000줄짜리 단일 파일은 화면별로 나눈다.

### 4단계: 디자인

레퍼런스를 정한 뒤 폰·워치 화면을 새로 만든다. Kyungmin이 레퍼런스(앱 스크린샷 등)를 고른다.

진행(2026-10-12): 운동 화면을 Compose로 재작성(폰 0.7.0). 공통 모션 규칙은 `phone/.../ui/Motion.kt`
(패널 300ms easeInOutCirc, 소변화 200ms easeInOut, 숫자 롤링 linear). 화면 내 키패드, 세트 완료→휴식 한 번에,
휴식 링 패널, 다음 세트 배너(6초 전), 3·2·1 진동·비프, 밀어서 세트 삭제+되돌리기, 세트별 휴식, 운동 간 스와이프.
나머지 화면(홈, 루틴, 기록)은 아직 기존 View 방식.

### 5단계: 기능 복원

루틴, 기록 달력, 휴식 타이머, 점진적 과부하 제안, 마이마운틴(웨이트 후 선택)을 새 구조 위에 다시 붙인다.

## 확정된 전제

- 운동 중 폰은 주머니나 기구 벽(전용 케이스)에 있다. 항상 블루투스 범위 안이므로 워치는 얇게 두고 폰이 두뇌를 맡는다. 순간 끊김에 대비한 워치 로컬 버퍼만 둔다.

## 정해야 할 것

- 4단계 디자인 레퍼런스
