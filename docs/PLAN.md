# KCoach 리부트 플랜 (2026-10-11)

> 현재 사용자 측정·보정 흐름은 [MEASUREMENT_FLOW.md](MEASUREMENT_FLOW.md)를 따른다. 아래 실측 프로브/3D 궤적 내용은 초기 연구 계획이며 일반 운동 측정이나 누적 학습의 현재 구현으로 해석하지 않는다.

> 2026-10-15 현재 소프트웨어 연결은 [측정 흐름](MEASUREMENT_FLOW.md)과 [GPT 이식 상태](GPT_IMPLEMENTATION_STATUS.md)를 따른다. 운동 보정 워커·사용자 엔진·종료 리뷰·상담과 코덱스1 후순위 병합은 연결됐고, 실제 계정/Watch8 성공과 촬영 초기화 해결·최종 통합 검사/공개는 아직 완료되지 않았다. 아래 날짜별 설명은 당시 이력이다.
>
> 2026-10-14 배포 순서 변경 승인: 사용자가 실측 자료 수집을 위한 선행 배포 질문에 “기존 앱 업데이트로 먼저 배포”라고 답했다. 폰 0.7.4(34)·워치 0.2.5(33)를 검증용 업데이트로 먼저 공개하고, 실기 검증과 나머지 작업 뒤 최종 배포한다. 삭제·재설치는 요구하지 않는다.

## 목표

손등 위 Galaxy Watch8 하나로 위 리모컨처럼 손목 움직임을 3D로 보여주고, 반복수·속도·반복 간 차이를 알려주는 개인 트레이너 앱.
워치는 센서 신호를 보내고 받기만 한다. 계산과 분석은 폰이 한다.

## 현재 작업 순서 — 2026-10-14 사용자 추가 예약

사용자는 진행 중에도 새 요구를 다음 순번에 추가할 수 있다고 명시했다. 아래 순서를 적용하고
기존 측정·보정·AI 범위와 최종 완료 감사/배포 목표를 유지한다.

1. **현재 긴급 작업: 촬영 엔진 초기화 실패.** 사용자가 폰 0.7.4·워치 0.2.5 업데이트와
   실행 성공을 확인한 뒤 `관절 인식을 시작하지 못했어요`를 보고했다. OTA가 MediaPipe JNI의
   필수 선언을 제거한 것을 실제 APK에서 확인했다. JNI 보존·원인 복사 기능을 수정한
   폰 0.7.5를 검증용 업데이트로 배포한 뒤 실제 초기화와 몸 인식을 다시 확인한다.
2. **그다음: 시작 2초와 운동별 손목 방향 검진.** 현재 StartPoseStabilityGate는 센서 안정성과
   그때의 중력 방향을 상대 기준점으로 확인한다. 운동별로 올바른 시작 방향인지는 검증하지 않는다.
   후속 사용자 추가 지시: 모든 종목에 정자세 2초 게이트를 일괄 적용하지 않는다. 확실한 수행 변형만
   지정된 손목 방향+안정 2초를 확인하고, 랫풀 등 그립/시작이 애매한 종목의 정자세 판정은 보류한다.
   [전체 종목 시작 방향 분류](START_WRIST_ORIENTATION_PLAN.md)를 먼저 확정한다.
   사용자가 제시한 케이블 익스터널 로테이션의 손바닥 위·워치 손등 착용 조건부터 설명 가능한
   시작 조건을 정리한다. 좌/우 손·손등/손바닥 착용·그립 변형을 분리하고, 손목으로 확인 가능한
   방향과 카메라/사람 확인이 필요한 어깨·팔꿈치 자세를 구분해 구현·검증한다.
   시작 방향 검사 공유는 손바닥 위/아래 수평 전완과 팔 내림 기울기의 두 관측 계열로 단순화한다.
   워치 본체 장착 방향도 확인하고, 조건이 없는 자료에 새 방향 기준을 추정해 붙이지 않는다.
   보류 종목은 명시적 시작으로 진행하며 정자세 확인을 이유로 2초를 강제하지 않는다.
   세 후보 역시 지정 변형과 실제 Watch8 검증 조건에서만 강제 방향 확인으로 승격한다.
   사용자 보고상 어깨 루틴 첫 운동 측정은 동작했으나 횟수 정확도 증거는 아직 없다.
3. **그다음: 폰 한 곳에서 폰·워치 업데이트.** 워치의 독립 `업데이트 확인` 버튼을 제거한다.
   2026-10-14 소프트웨어 연결/OTA 축소 검사까지 진행했다. 현재 흐름과 첫 통합 버전의 전환은
   [통합 업데이트 흐름](COMPANION_UPDATE_FLOW.md)을 따른다. 실물 설치/재연결 검증은 남아 있다.
   폰에서 한 번 확인하면 연결된 워치에도 확인 요청을 보내고 기기별 설치 버전/manifest를 비교한다.
   폰만 새 버전·워치만 새 버전·둘 다·둘 다 최신의 네 조합을 검사한다. 새 버전이 있는 기기만
   다운로드/설치 요청을 진행하고, 워치에는 실제 진행 상태와 운영체제가 요구하는 설치 확인을 보여준다.
   연결 끊김·재연결·중복 요청·설치 중 앱 종료를 처리하고 실제 설치 버전 응답 전에는 성공으로
   표시하지 않는다. 폰 버튼으로 워치 APK 설치까지 무조건 무인 완료된다고 가정하지 않는다.
4. **이어서 기존 범위:** 실제 Watch8/영상 검증·측정 엔진 채택·개인 보정·관측 지표,
   프로필·상담·종료 리뷰·GPT 보정·누적 최적화와 최종 완료 감사/배포를 계속한다.
   로컬 AI 상담/프로필 연결 작업은 보관됐으며 촬영 긴급 수정에 섞어 배포하지 않는다.
5. 워치 운동 화면 전반의 추가 개선은 위 우선 작업 후 사용자와 항목을 정리한다.

## 원칙

- 살리는 것: `core` 알고리즘(반복 감지, 보정 프로필, 운동 카탈로그)과 GitHub 업데이트.
- 새로 짜는 것: 폰·워치 화면, 센서 수집, 폰↔워치 연결.
- 숫자로 확인하기 전에는 측정 방식을 확정하지 않는다.
- 배포는 항상 `tools/release.sh`. ADB는 쓰지 않는다.

## 단계

### 0단계: 인터넷 업데이트 — 완료

GitHub Releases로 전환. 폰 0.5.12, 워치 0.1.26 설치 완료. 실제 GitHub 경유 업데이트는 1단계 배포가 첫 실전.

### 1단계: 실측 프로브

기존 앱에 "실측 모드" 화면을 추가해 업데이트로 배포한다.

| 재는 것 | 방법 | 합격 기준 |
|---|---|---|
| 센서 속도 | 워치 화면 켜짐/꺼짐에서 가속도·자이로 실제 Hz | 세트 중 50Hz 이상 유지 |
| 폰 전송 | 워치→폰 실시간 스트림의 지연·누락 | 지연 0.5초 이하, 누락 1% 이하 |
| 3D 궤적 | 반복 상·하단 정지점마다 0점 리셋한 손목 궤적을 폰 3D 화면에 표시 | 같은 동작 반복이 눈으로 비슷한 모양 |
| 업데이트 속도 | 압축 빌드로 워치 APK 크기 줄이기 | 6MB 이하, 다운로드 1분 이내 |

테스트 운동: 덤벨 컬, 랫풀다운, 체스트프레스 (손목 움직임이 큰 것부터).

### 2단계: 측정 방식 확정

1단계 숫자를 보고 결정한다.
- 반복 카운트: 기존 `core` 상태 머신으로 시작하고, 실제 세트 데이터에 실제 횟수를 붙여 모은다. 데이터가 쌓이면 폰에서 학습 모델로 교체를 검토한다.
- 3D 궤적: 1단계 결과가 좋으면 정식 기능, 아니면 손목 각도·회전만 표시.

### 3단계: 새 구조

- 워치: 센서 수집 + 로컬 저장 + 폰으로 스트림. 화면은 최소(세트, 횟수, 휴식, 심박).
- 폰: 세션 진행, 분석, 기록, 3D 표시.
- 연결: 실시간 스트림, 끊기면 워치에 저장했다가 다시 붙으면 이어서 전송.
- 폰 4,000줄짜리 단일 파일은 화면별로 나눈다.

### 4단계: 디자인

레퍼런스를 정한 뒤 폰·워치 화면을 새로 만든다. Kyungmin이 레퍼런스(앱 스크린샷 등)를 고른다.

진행(2026-10-12): 운동 화면을 Compose로 재작성(폰 0.7.0). 공통 모션 규칙은 `phone/.../ui/Motion.kt`
(패널 300ms easeInOutCirc, 소변화 200ms easeInOut, 숫자 롤링 linear). 화면 내 키패드, 세트 완료→휴식 한 번에,
휴식 링 패널, 다음 세트 배너(6초 전), 3·2·1 진동·비프, 밀어서 세트 삭제+되돌리기, 세트별 휴식, 운동 간 스와이프.
나머지 화면(홈, 루틴, 기록)은 아직 기존 View 방식.

### 5단계: 기능 복원

루틴, 기록 달력, 휴식 타이머, 점진적 과부하 제안, 마이마운틴(웨이트 후 선택)을 새 구조 위에 다시 붙인다.

## 확정된 전제

- 운동 중 폰은 주머니나 기구 벽(전용 케이스)에 있다. 항상 블루투스 범위 안이므로 워치는 얇게 두고 폰이 두뇌를 맡는다. 순간 끊김에 대비한 워치 로컬 버퍼만 둔다.
