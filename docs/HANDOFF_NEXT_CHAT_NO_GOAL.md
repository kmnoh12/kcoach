## 빌드 시간 단축 설정 (이번 세션 후속 변경)

- `gradle.properties`: `org.gradle.caching=true`. R8 최적화·리소스 축소 및 2GB 힙 설정은 유지한다. configuration cache/과도한 병렬화는 추가하지 않았다.
- `tools/release.sh`: 기본은 최신 공개 릴리스 기준으로 변경 앱만 빌드한다. core/updates/공용 빌드 설정 변경은 양쪽 빌드 대상이다. 기준 커밋을 확인할 수 없으면 범위를 명시하도록 중지한다.
- `--phone`, `--watch`, `--both`로 빌드 범위를 명시할 수 있다. 이 옵션으로 공용 변경의 영향을 무시하지 않는다.
- `--publish-built`는 선택한 APK를 그대로 배포하며 APK가 없으면 실패한다. 자동 빌드로 전환하지 않는다. 현재 소스로 만든 APK라는 사실이 확인된 경우에만 사용한다.
- 변경 없는 앱은 기존 공개 APK를 사용한다. 로컬 공개 아티팩트 캐시가 공개 manifest 해시와 같으면 재다운로드도 생략한다.
- 기본 배포는 전체 테스트/lint를 실행하지 않는다. `--full-check`는 사용자가 전체 검사를 명시적으로 요청한 경우에만 준다.
- 긴 빌드 출력은 `work/release/build.log`로 보내며 실패 시 관련 줄만 출력한다. 업로드할 파일의 서명·버전·해시와 변경한 폰 APK의 기존 JNI 선언만 짧게 확인한다. 화면·설치 검사는 하지 않는다.
- 이번 변경은 셸 문법 확인만 수행했다. 빌드·테스트·배포·실제 속도 측정은 실행하지 않았다. 다음 에이전트가 이 설정을 이유로 벤치마크/전체 검사를 시작하지 않는다.
