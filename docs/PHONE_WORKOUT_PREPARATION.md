# 폰 기본 프로필과 루틴 시작 준비 — 2026-10-15

후속 소스 구현 기록이다. 공개 APK 0.7.8에 포함됐다는 뜻이 아니다.
코덱스1의 폰 중심 준비 동선과 사용자의 후속 요청을 반영하며,
카메라 측정 전 가상 모범 동작은 사용자가 클로드와 기획 중이므로 이번 수정 대상에서 제외한다.

## 사용 흐름

설정의 첫 영역에서 `내 운동 프로필 · 워치 착용`을 연다. ChatGPT 로그인 없이 키·나이·성별·체중,
선택적인 체지방률·골격근량과 착용 손/면을 저장한다. 모르는 신체 수치는 null/빈 값으로 유지한다.
착용 손과 면은 둘 다 선택하거나 모두 미설정으로 두며 절반만 저장하지 않는다.

루틴 상세와 자유운동의 빈 고정 높이 영역을 없애고, 내용 높이에 맞춘 준비 영역을 표시한다.
워치 연결 조회 결과와 저장된 기본 착용을 요약하고 설정으로 연결한다. 설정에서 돌아오면 다시 읽는다.
현재 루틴에 실제 포함된 외회전/리버스 플라이/덤벨 사레레만 시작 방식 질문을 표시한다.
각 질문의 `이 방식`/`다른 방식`/`모름`은 구분하며 저장한 선택이 있으면 다시 표시한다.
저장한 답변이 없으면 확인됐다고 추정하지 않는다. 질문의 필요성/최종 구성은 코덱스1과 재검토 중이다.
랫풀/로우 등 보류 종목에는 시작 방식 질문을 추가하지 않는다.

폰의 기존 시작 버튼은 바로 세션을 저장하고 START를 전달한다. 시작 뒤 착용 손·면을 다시 묻는
WorkoutWearingStartSheet는 제거했다. 운동 미리보기의 세트 완료/전체 완료에서 시작하는 경로도
같은 직접 시작 함수를 사용한다. 기본 착용이 미설정이면 개인 보정 없이 시작할 수 있다.
설정 읽기 실패를 미설정과 구별하며 실패 시 조용히 기본값을 지우고 시작하지 않는다.

## 저장과 조건 경계

- 기존 AtomicFile `ai-coach.json` 안의 device_profile에 기본 신체·착용을 함께 저장한다.
  별도 로그인이나 새로운 계정/운동 소유자를 만들지 않는다. revision으로 오래 열린 편집의 덮어쓰기를 막는다.
- 기존 accounts/session_owners는 자동으로 바꾸지 않는다. 상담 화면의 명시적
  `폰 기본 신체정보 불러오기`만 선택 계정의 신체 필드를 복사한다. 계정 ID/목표/기구/연결 기록은 유지한다.
  이 동작은 모델 요청을 하지 않는다. 신체정보가 비어 있으면 가져온 계정에서도 미입력으로 반영된다.
- 착용 손·면과 해당 루틴 답변은 WorkoutWearingStore의 기존 세션/시도 조건에 고정한다.
  시작 뒤 설정 변경이나 다른 루틴의 답변으로 진행 중인 시도의 조건을 바꾸지 않는다.
  답변은 기존 workout-wearing 저장소의 preparation-answers에 종목별로 즉시 저장한다.
  기존 마지막 세션 답변을 초기값으로 읽고, 다른 루틴을 시작해도 다른 종목의 선택을 잃지 않는다.
  재실행/새 운동에서는 이 선택을 재사용하되 센서 검증 완료로 승격하지 않는다. 명시적 모름도 보존한다.
- 새 기본 신체정보도 시작 시 deviceBodyProfile로 함께 고정한다. 나중의 체중 수정으로 과거 새 세션의
  칼로리 입력을 소급 변경하지 않는다. 이전 세션은 기존 계정 소유/칼로리 판정 경로를 유지한다.
- `본체 위쪽이 향하는 곳`은 일반 준비 화면에서 제거한다. 손/착용 면으로 물리적 센서 방향을
  추정하지 않으며 deviceTop은 UNKNOWN으로 전달한다. 방식 답변만으로 방향 검증 완료가 되지 않는다.

## 대상 검증

전체 테스트/lint/OTA 빌드나 reviews JSON을 반복하지 않았다. --tests로 수정 경로만 실행했다.

- work/device-profile-focused.log: 로그인 없는 저장/착용, 기존 착용 조건, 계정 컨텍스트와 UI 대상 검사.
- work/device-profile-snapshot-focused.log: 시작 신체 스냅샷/과거 세션/AI 비교 연결 대상 검사.
- work/device-profile-account-import-focused.log: 계정 선택 가져오기/컨트롤러/상담 UI 대상 검사.
- work/routine-preparation-focused.log: 실제 기본 어깨 루틴의 세 질문, 보류/중복/다른 방식/미확인,
  선언과 검증 방향 분리, 기존 시도 동결, 준비 UI/기존 시작 조건/상담 UI 대상 검사.
- work/routine-preparation-layout-focused.log: 긴 준비 영역의 스크롤과 고정 시작 버튼/프로필 대상 검사.
- work/routine-preparation-render-focused.log: 네이티브 Robolectric 화면 렌더링과 대상 컴파일/저장 검사.
- work/routine-preparation-remembered-focused.log: 최신 요청인 선택 재사용/재실행/다른 루틴/기존 운동 불변과
  관련 저장·시작 조건·UI/프로필의 대상 재확인. 이전의 매 운동 초기화 초안은 최종 동작이 아니다.
- work/routine-preparation-legacy-migration-focused.log: 이전 선택을 읽기만 한 뒤 다른 루틴을 시작해도
  이전 선택이 사라지지 않도록 기존 마지막 세션 값을 보존하는 마이그레이션과 시작 조건 대상 검사.

렌더링은 폰 기기 실행이 아니다. 공개 APK 제작/설치 및 실제 폰→워치 직접 시작은 아직 미확인이다.

## 다음 범위

코덱스1의 새 워치 대기/운동/휴식/완료 구성은 승인된 최종 구현을 기다린다. 첫 시안 e25063c를
최종 결과로 병합하지 않는다. 완료 화면의 `폰에서 보기`와 정확한 완료 세션으로 여는 경로도 함께 조정해야 한다.
기기별 물리 방향 설정은 식별 가능한 그림/설명·확인 근거가 필요하며 이번 기본 손/면 설정으로 대체하지 않는다.
카메라 모범 동작은 클로드 기획 수령 후 별도 범위를 맞춘다. 0.7.8의 실물 관절 표시 성공,
Watch8 정답 자료에 의한 개선, 실제 계정 모델 호출은 여전히 확인되지 않았다.
모든 후속 구현과 병합이 끝난 뒤 최종 전체 검사/lint/OTA 및 tools/release.sh 배포를 진행한다.

담당 경계와 미확정 UX는 [병행 작업 분담](PARALLEL_WORK_BOUNDARIES.md)을 함께 따른다.
