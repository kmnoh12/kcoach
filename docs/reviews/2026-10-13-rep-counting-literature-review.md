# 워치 횟수 측정 문헌 재검증과 적용 방향

2026-10-13. 사용자가 제공한 `스마트워치 렙 카운팅 소스 모음.html`을 출발점으로,
논문 9편의 방법·평가·결과에서 필요한 부분, 추가 논문 1편의 공식 초록,
공개 저장소 2개의 실제 소스와 현재 워치짐 소스를 대조했다.
모든 출처 60여 개를 검증한 보고서는 아니다. 알고리즘 변경이나 실제 Watch8 실험은 수행하지 않았다.

## 재검증으로 바로잡은 판단

첫 답변은 참고 자료를 충분히 읽기 전에 한계를 강조했다. 특히 아래 두 부분을 수정한다.

- **주요 축 → Savitzky–Golay 필터 → 운동별 이중 임계값 → 최대·최소 한 쌍**은
  Sensors 2020, 20, 4791의 §2.3.3에 실제로 한 파이프라인으로 기술되어 있다.
  구성 요소를 모아 만든 근거 없는 조합으로 취급하면 안 된다. 구현·비교할 가치가 있는 선행 방법이다.
- van Hooff 논문을 가설 문구만 확인하고 평가하면 부족하다. 실제 실험과 개인/평균 프로필 비교가 있다.
  다만 최종 결론은 첨부의 “개인 보정 필수”와 다르다. 개인 프로필을 유지할 이유는 있지만,
  평균 프로필도 쓸 수 있다는 결과다.

논문이 보여준 결과와 실험 조건을 함께 따른다. 우리 기존 구현을 기준 정답으로 두지 않는다.

## 1. 바로 비교할 신호 처리 방법

[Prabhu et al., Sensors 2020, 20, 4791](https://www.mdpi.com/1424-8220/20/17/4791),
출판사 PDF §2.1, §2.3.3, §3.3, 표 2/7/8을 확인했다.

76명, 손목 Shimmer3, 512Hz, 10종 운동이고 여러 운동에 1kg 덤벨을 사용했다.
주요 축을 운동별로 고른다. 컬/프런트레이즈/레터럴레이즈/삼두 익스텐션은 가속도 X,
펙덱은 자이로 X, 몸통 회전은 자이로 Y다.
가속도와 각속도는 단위가 다르므로 여섯 채널의 원시 에너지 숫자를 무조건 직접 비교하는 것으로 옮기지 않는다.
SG 필터는 1023샘플, 4차이고 최대·최소 쌍을 센다.

피크 방식의 정확 일치 세트는 컬 144/151, 레터럴레이즈 141/150, 삼두 143/152였다.
반면 런지는 11/147로 낮았다. “모든 운동에 통하는 정답”이 아닌 운동별 성공/실패를 가진 방법이다.
CNN 결과는 별도 참가자 테스트에서 전체 90% 세트가 ±1회 이내였다.
피크 평가와 CNN 평가의 표본 수·평가 절차가 같지 않다는 점도 비교에 남긴다.

**적용:** 운동이 이미 선택된 우리 앱에서는 선행 종목 분류를 생략할 수 있다.
현재 방식과 별도로 논문 기반 피크 방식을 재생 비교한다. 먼저 컬/레이즈/삼두가 대상이다.
논문의 1023/512는 약 2초 창이다. 같은 1023샘플을 50Hz에 적용하면 약 20.46초가 된다.
이는 창 길이 계산이며 실제 지연 측정은 아니다. 실시간에서는 인과적 필터의 지연을 측정하고,
폰의 세트 종료 후 재분석에서는 미래 샘플을 쓰는 필터를 별도로 평가한다.

## 2. 개인 프로필의 근거와 유지 기간

[Nino van Hooff, 2013 석사논문](https://www.ai.rug.nl/~mwiering/Thesis_nino_van_hooff.pdf),
§2.2.2–2.2.4, §3.1–3.5, §6.2를 확인했다.

손목에 스마트폰을 부착하고 전진/복귀 동작의 시작·끝 진폭과 시간을 추출한다.
이상치를 제거해 개인 기준과 허용 편차를 만들고 새 동작과 비교한다.
71명이 첫 실험에 참여했고 41명이 일주일 뒤 돌아왔다.
주요 평가인 컬/벤트오버로우의 당일 프로필 비교 점수는 95.3%, 일주일 간격은 89.1%다.
이는 정확 일치 세트 비율과 다르다. 표 3.1에는 별도의 정확 일치 파일 수가 있다.

같은 비교에서 개인 모델 87.2%, 평균 모델은 보조 축 허용 범위를 넓힌 후 82.1%였고
통계적으로 유의한 차이는 아니었다. §3.4는 횟수 측정에 개인 프로필이 반드시 필요한 것은
아니라고 결론 내린다. 목표/능력 차이를 위해 개인 프로필 기능은 권장한다.

**적용:** 평균 운동 프로필을 기본값으로 제공하고 좋은 기준 동작으로 개인화한다.
“보정하면 영구적으로 정확” 대신 날짜·착용 상태·운동 조건을 함께 저장한다.
당일 보정 성적뿐 아니라 다음 날/다음 주 성적을 비교한다.
다른 운동·장비·착용 방향의 자료를 한 프로필에 무조건 합치지 않는다.

## 3. 템플릿 비교는 가벼운 학습 후보

[ExerSense, Sensors 2021, 21, 91](https://www.mdpi.com/1424-8220/21/1/91),
§3, §4, 표 2/3을 확인했다. 15명, 걷기/달리기/점프/푸시업/싯업과 네 착용 위치다.
분할한 동작을 기준 템플릿과 비교하는 접근이며 DTW도 기술한다.
손목의 전체 분할 재현율은 0.916, 템플릿 무작위 선택 시 평균 분류 정확도는 0.835였다.
푸시업 분할 재현율 0.904를 손목 푸시업 세트 전체의 정확 일치 비율로 바꾸어 말하지 않는다.

**적용:** 거대한 모델을 먼저 훈련하지 않고 정상 반복 몇 개의 시간 정규화 패턴과
후보 반복을 비교할 수 있다. 기준 동작 선택 품질과 속도 변화 허용 범위를 평가한다.
“손목 고정이면 어떤 알고리즘으로도 측정 불가”라는 보편적 단정은 하지 않는다.
우리 앱의 수동 정책은 현재 검증 수준에 따른 제품 정책으로 유지한다.

## 4. few-shot 개인화에서 가져올 원칙

[BayaHAR, arXiv 2606.04798v2](https://arxiv.org/html/2606.04798v2),
§4–6과 표 1/2를 확인했다. 사전 학습된 HAR 분류기의 임베딩에 대해 개인 프로토타입을
베이지안 방식으로 갱신한다. 4개 데이터셋, 3초 창, LOSO 평가이며 보정 support와 평가 query를 분리한다.
1샷당 macro-F1 +2.76~33.44%p는 동작 분류 성적이다.

**적용:** 이 향상치를 우리 횟수 성적에 대입하지 않는다. 대신 **일반 기준을 prior로 남기고,
자료 수와 불확실성에 따라 개인 자료의 반영량을 달리하는 설계**를 참고한다.
우리 코드의 고정 80:20 혼합보다 검증할 만한 후보다. 이 논문의 프로토타입 갱신은
단순 임계값 갱신과 동일한 알고리즘은 아니다.

## 5. 카메라+IMU는 실제 선행 연구가 있다

[Sensors 2026, 26, 5838](https://www.mdpi.com/1424-8220/26/18/5838),
§2.1/2.3/2.5/2.8, §3, §4 한계를 확인했다.
JY901 9축 IMU 200Hz + MediaPipe 영상 30FPS + 로컬 워크스테이션이다.
10명, 푸시업/싯업/스쿼트 900반복, 참가자를 분리한 LOSO 평가에서 종목 분류 96.0%다.
타임스탬프 근접 매칭·선형 보간과 시각 신뢰도에 따른 융합이 구체적으로 기술되어 있다.
독립적인 시작/끝 라벨을 보존하지 않아 분할 경계 성적을 평가하지 못했다는 한계도 명시한다.

**적용:** 카메라/IMU 시계 정렬, 가림·신뢰도 처리, 분기별 출력 비교를 가져온다.
논문의 워크스테이션 성적이 우리 폰·워치 실시간 성능을 검증한 것은 아니다.
보간은 실제 관측을 추가하지 않는다. 가려진 구간을 학습 정답으로 채우지 않는다.
카메라를 껐을 때 워치 성적이 좋아지는 “교사→워치” 구조는 별도 실험이다.

[Singh et al., arXiv 2307.04516](https://arxiv.org/pdf/2307.04516), §3–5에서는
54명의 밀리터리프레스/로우 수행을 정면 영상과 5개 IMU로 비교했다.
여기서 분류는 단순 종목 선택이 아니라 정상/비대칭/가동범위 부족/등 자세 등의 수행 종류를 구별하는 과제다.
단일 카메라+단일 IMU 앙상블은 각 모달리티 단독보다 좋았다.
따라서 영상/센서의 상호 보완은 타당한 참고이고, 횟수 정확도 보장으로 해석하지 않는다.

## 6. 횟수 경계와 근접 실패 추정의 학습

[Rep Smarter, Not Harder, arXiv 2512.11854](https://arxiv.org/pdf/2512.11854),
§II–III를 확인했다. 13명, 프리처컬 68세트/631반복, 손목 6축 IMU 약 100Hz다.
반복 끝 라벨로 ResNet 분할, 분할 특징과 시계열로 LSTM 기반 근접 실패 분류를 수행한다.
분할 F1 0.83, 근접 실패 F1 0.82다. 학습/검증은 세트 단위로 분리했고 새 사용자 분리 평가와 같지 않다.
폰 Core ML 추론과 워치 데이터 전송도 설명한다.

**적용:** 횟수 끝 경계 라벨을 저장하면 작은 전용 센서 모델을 학습할 길이 있다.
현재 자료 없이 RIR 숫자를 자동 추정하는 기능부터 넣지 않는다.
사용자·날짜를 분리한 시험을 추가하고 우리 워치 좌표계/샘플링에 맞게 검증한다.

## 7. 3D는 학습된 센서 모델의 과제

[ArmPoser, arXiv 2609.08806v1](https://arxiv.org/html/2609.08806v1), §4–6을 확인했다.
30Hz 워치 신호로 팔 자세를 추론하고 약 170ms의 입력 지연이 있다.
프로토타입 추론은 MacBook Air에서 실행했다. 추가 실험의 기준 자세는 보정된 RGB 카메라 6대의 EasyMocap이다.
여러 데이터셋 평균 손목 위치 오차 중앙값은 10.27cm, 팔꿈치는 5.81cm다.

**적용:** 착용 방향 변화와 좌표계 정규화·증강을 참고한다.
3D를 원천 불가능으로 취급하지 않되, 현재 IMU 그림을 학습 모델의 관절 위치 추정과 혼동하지 않는다.
셀카 1대의 MediaPipe도 이 실험의 다중 카메라 기준과 같은 정밀도로 간주하지 않는다.

## 8. 빠른 반복과 전체 세트 평가

[Soro et al., Sensors 2019, 19, 714](https://www.mdpi.com/1424-8220/19/3/714),
§3, §5.2, §6을 확인했다. 손목·발목 센서, 54명, 5461반복의 CrossFit 데이터다.
제약된 수행에서 전체 세트 MAE 0.70, 정확 일치 73.5%, ±1회 90.8%였다.
빠르게 이어지는 비제약 수행으로의 일반화가 일부 종목에서 나빠졌고,
그런 영상의 반복 시작 라벨을 추가할 계획을 설명한다.

**적용:** 카메라 보정 때만 일부러 정지시킨 자료로 학습하면 실제 빠른 세트에서 실패할 수 있다.
평소 속도/느린 속도/빠른 속도와 피로 후반부를 모두 검증하고 정확 일치·MAE·±1을 함께 보고한다.

[Pūioio, arXiv 2308.02420](https://arxiv.org/pdf/2308.02420), §2–3을 확인했다.
관련 연구 정리와 함께 BlazePose, 관절 기준, 광학 흐름, 상태기계 기반 폰 카메라 카운터를 제시한다.
시각 신뢰도 부족 시 대체 경로·중단 처리를 참고한다. 이 논문 자체는 워치 학습 연구가 아니다.

## 9. 99.4%의 원출처

[Das et al., IEEE ICMLA 2017 공식 초록](https://ieeexplore.ieee.org/document/8260796/)에서
종목 인식 95.3%, 횟수 측정 99.4%를 확인했다. 존재하지 않는 수치는 아니다.
이번 확인에서는 본문·참가자 수·횟수 성적의 세부 계산식을 확보하지 못했다.
우리 제품 목표치를 정할 근거로 사용하기 전 이 부분을 추가 확보해야 한다.

## 10. 공개 소스에서 실제 확인한 범위

- [strength_tracker](https://github.com/advaithmalka/strength_tracker/tree/a59f7ccbb654319d92dc7e8a45c7341c6a512d4c), MIT.
  `RepDetector.swift`의 factory는 왼손 `Lateral Raise`만 지원한다.
  실제 탐지기는 중력 기준 35° 이탈·18° 복귀, 휴지/시간 조건, 고정 confidence 0.5다.
  주석도 실제 기록으로 보정할 임시 기준이라고 명시한다. 구조 참고용이며 검증된 범용 카운터가 아니다.
- [VideoIMUCapture-Android](https://github.com/CiaCrystal/VideoIMUCapture-Android/tree/d79cc6f0d1f4ed9a9001ee4831edacc9ab232ae3), GPL-3.0.
  `IMUManager.java`는 센서 이벤트 시각을, `Camera2Proxy.java`는 프레임 SENSOR_TIMESTAMP와
  기기의 timestamp source를 보존한다. 같은 폰의 영상/IMU 동기화 참고다.
  별도 워치와 폰의 부팅 기준 시계가 같아지는 것은 아니다. 코드 복사 시 라이선스 검토가 필요하다.

## 현재 워치짐에서 확인한 차이

대조 대상은 현재 작업 폴더다. 기존 변경은 보존했고 코드 실행/수정은 하지 않았다.

| 현재 확인한 코드 | 문헌을 참고해 평가할 부분 |
|---|---|
| `ReturnToPoseRepDetector`는 고정 60° 이탈/20° 복귀, 필터 시정수 0.15초 | 출발·복귀 진폭과 왕복 패턴의 운동별/개인별 설정 후보 |
| `ProfiledMotionRepDetector`는 컬에서 위 감지기에 `minimumRepMs`만 전달 | 개인 프로필을 만들어도 이탈/복귀 각도는 개인화되지 않음 |
| 다른 계열은 초기 임계값을 넘은 순간 가장 큰 축을 잠그는 방식 | 여러 기준 반복 전체에서 선택한 운동별 축/투영과 비교 |
| `PersonalCalibrationBuilder`는 기존 감지기의 이벤트로 기준을 만들고 80:20 혼합 | 독립적으로 확인한 반복 구간을 써서 자기 오탐을 학습하는 순환을 줄이기 |
| 워치 개인 프로필 저장 조회는 exerciseId 기준, 현재 프로필 적용 | 여러 보정 자료·날짜·조건·모델 버전의 유지 및 검증 후 갱신 |
| 카메라 코어는 고정 각도 상태기계 초안 | 실제 카메라/워치 수집·동기화·라벨 검증이 먼저 필요 |

## 구현 전에 정할 비교 실험

1. **기준 데이터:** 같은 Watch8의 원본 IMU, 영상/관절 궤적, 사람이 확인한 반복 시작·끝,
   착용 손/방향, 운동 변형, 중량, 날짜, 실제 샘플 간격/공백을 저장한다.
   총 횟수만으로 내부 반복 경계가 맞았다고 판단하지 않는다.
2. **동기화:** 폰·워치 단조 시계 차이를 왕복 교환으로 추정하고 오차 범위를 남긴다.
   두 신호에서 관측 가능한 동작으로 정렬을 확인한다. 시작/중간/끝 오프셋과 드리프트를 비교한다.
   수신 시각만으로 정답 경계를 붙이지 않는다. 가림/공백을 보간해 정상 라벨로 만들지 않는다.
3. **동일 입력 비교:** 현재 고정 복귀 방식, 논문 기반 주요 축/SG/이중 임계값,
   개인 진폭·시간 패턴, 템플릿 비교를 같은 시험 세트에 재생한다.
   공개 데이터는 구현 확인·외부 비교용이고 Watch8 검증을 대체하지 않는다.
4. **누적 보정 검증:** 첫 기준 세트로 다음 세트를 평가하고, 확인된 자료를 추가한 뒤
   아직 쓰지 않은 다음 날 세트를 평가한다. 고정 보정·최근 자료만·누적 갱신을 비교한다.
   매번 다음 시험 자료를 보고 임계값을 바꾸지 않는다.
5. **보고 기준:** 운동별 정확 일치/MAE/±1, 반복 경계 오차, 실시간 지연,
   거절/미측정 비율, 후반·빠른 동작·착용 변경 성적을 함께 보고한다.
   처리한 일부 구간의 좋은 성적만 발표하지 않는다.
6. **채택:** 개선이 확인된 운동/조건부터 적용한다. 확인 실패 시 이전 프로필을 유지한다.
   더 어려운 경우 작은 전용 센서 모델을 검토한다. LLM이 필요하다고 전제하지 않는다.

이 실험 순서는 논문들의 방법과 한계를 바탕으로 작성한 **우리 앱의 제안**이다.
아직 실행한 실험이나 성능 향상 결과가 아니다. 사용자에게 작업 계획을 설명한 뒤 구현으로 이어간다.
