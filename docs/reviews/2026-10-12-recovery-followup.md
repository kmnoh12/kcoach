# 복구 구조 리뷰 후속 검사

2026-10-12. 사용자가 제공한 22:55 KST 스냅샷 리뷰의 세 결함에 대한 후속 수정이다. 기존 개선 전체를 되돌리지 않았다. 실기기 안정성 완료로 판단하지 않는다.

## 재부팅 이후 원본 수집

수정 전: 이전 부팅의 86,400초 센서 시간을 복원한 상태에서 새 부팅의 10초 샘플이 수집되지 않았다. 시간만 초기화해 한 KCS에 붙이는 방법도 유효하지 않다.

수정 후: BOOT_COUNT와 저장 시 uptime으로 부팅 변경을 구분한다. 이전 구간을 기존 불완전 기록 구조에 보존하고, 새 구간에는 별도 고유 ID를 붙여 수집한다. 같은 세트/시도라도 구간 파일명이 겹치지 않는다. 같은 부팅의 서비스 재생성은 기존 파일을 이어 쓴다. 구형 런타임/부팅 정보를 확인할 수 없는 경우에는 복원 후 첫 센서 시간 역행을 보수적으로 분리한다. 손상된 원본 복구가 먼저 실패한 경로에서도 부팅 변경을 처리한다.

검사는 현재 구간 1샘플과 보존 구간 1샘플의 합계 2샘플, 이전 86,400초 값 보존, 새 10초 값 보존, 각각의 KCS 시간 유효성을 확인한다. 리뷰의 단일 메모리 카운터 검사에 파일 보존·유효성 조건을 보강했다. 두 시간 기준을 한 파일에 합치지 않으므로 현재 구간의 내부 카운터는 1이다. 부팅에 걸쳐 중단된 시도는 자동 확정용 정상 완료 manifest로 전송하지 않고 두 구간을 보존한다.

이 검사는 Robolectric에서 부팅 번호와 센서 시간을 바꾼 서비스 검사다. 실제 기기 전체 재부팅은 미실행이다.

플랫폼 근거: [SensorEvent.timestamp](https://developer.android.com/reference/android/hardware/SensorEvent#timestamp)는 elapsedRealtimeNanos와 같은 시간 기준이며, [Settings.Global.BOOT_COUNT](https://developer.android.com/reference/android/provider/Settings.Global#BOOT_COUNT)는 부팅 횟수를 제공한다.

## 휴식 재개 식별자

START → REST → PAUSE → RESUME에서 세트 ID가 빈 값으로 바뀌던 검사가 수정 전 실패했다. 합성 REST에 기존 세션·운동·세트·시도·목표·중량을 전달한 뒤 세트 ID와 시도 ID가 유지되는 검사가 통과했다. 실제 워치 휴식 화면/폰의 실시간 수신은 실기기 확인이 남아 있다.

## 시작 복구 비용

MainActivity.onCreate의 완료 기록 전체 복구를 제거하고 기존 리스너 작업자에서 실행한다. 세션별 캡처 ID 인덱스와 분석 revision을 결과와 함께 저장하고, 완료 기록이 소비한 revision을 보존한다. 초기 구형 자료는 한 번 순회한다. 이후 복구 대상은 미반영/분석 변경 세션이며, 대상 세션의 분석만 읽고 정렬한다. 변경 없는 구형 완료 기록의 이관 표시는 묶어서 저장한다.

리뷰와 같은 자료 생성 방식(완료 세션당 분석 1개, 이미 반영된 6회 수행값)으로 측정했다. 시작 화면을 띄우는 전체 시간이 아니라 저장소의 replay 실행 시간이다.

| 세션/분석 수 | 수정 전 | 수정 후 첫 이관 | 수정 후 재실행 |
|---:|---:|---:|---:|
| 100 | 62ms | 22ms | 4ms |
| 500 | 439ms | 60ms | 7ms |
| 1,000 | 1,038ms | 54ms | 11ms |

수정 전과 후는 이 Mac의 별도 Robolectric 실행이다. 각각 준비 자료 20개로 워밍업했다. 측정치는 JVM/JIT/실행 조건에 따라 달라지며 실제 폰의 시작 시간·ANR·배터리 개선률로 해석하지 않는다. 시간 임계값으로 flaky한 합격 판정을 만들지 않았다. 변경 없는 재실행은 재처리 대상 0개, 새 분석을 저장하고 반영 전에 종료한 상태는 그 세션 1개만 처리하는 조건으로 검사했다. Activity 생성 시 완료 기록을 주 스레드에서 수정하지 않는 조건도 검사했다.

## 최종 검증

- core 118 + phone 127 + wear 39 = 284건, 실패/오류 0건.
- 폰·워치 debug APK 및 Roborazzi PNG 생성 통과.
- 리뷰의 재부팅/휴식 실패를 재현한 검사와 후속 검사 통과.
- 기존 화면 없는 완료, ID/수동 입력 보호, 늦은 분석·기록 복구 검사 유지.
- 배포, push, 앱 버전 변경 없음.

실제 화면 꺼짐, Bluetooth 단절·복귀, 전체 워치 재부팅, OS 종료와 배터리는 미검증이다. 절차는 `docs/DEVICE_VALIDATION.md`에 있으며 기기를 연결할 수 있을 때 수행한다. 전체 안정성 완료로 승인하는 근거는 아직 아니다.
