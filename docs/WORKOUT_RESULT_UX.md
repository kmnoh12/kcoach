# 운동 종료 결과 화면 — 즉시 요약과 후속 세부 분석

2026-10-14 사용자 요청. [GPT 적용 계획](AI_COACH_PLAN.md)의 종료 결과 화면 상세 명세다.
현재 측정 개편을 마무리한 뒤 구현할 후속 범위이며 실제 앱 화면 구현 완료를 뜻하지 않는다.
시안은 [결과 화면 미리보기](mockups/workout-result.html)이며 모든 숫자는 예시 데이터다.

2026-10-14 병행 구현: 기존 결과 화면 하단에 수동 AI 리뷰 요청·v2 검증·저장·펼침을 연결했다.
아래 명세 전체가 끝난 것은 아니다. 자동 종료 리뷰, 칼로리·심박·전체 즉시 요약과 실기 검증은 남았다.
[현재 구현과 남은 범위](WORKOUT_AI_REVIEW_HANDOFF.md)를 참고한다.

## 종료 직후

완료 기록을 저장하고 로컬에 있는 데이터로 즉시 결과 화면을 연다. 센서 전체 원본 수신,
MediaPipe/워치 세부 재분석 또는 GPT 응답을 기다린 뒤 화면을 여는 구조로 만들지 않는다.
초기 표시 목표는 저장 완료 후 1초 이내이며 실제 기기에서 계측한다.

위에서 아래로 다음 순서를 사용한다.

1. 운동 완료 제목, 날짜·루틴명, 저장 상태.
2. 큰 운동 시간, 완료 세트수, 총 볼륨, 추정 활동 칼로리. 단위와 작은 설명을 가까이 배치한다.
3. 평균/최고 심박과 운동 경과 시간 기준 심박 그래프.
4. 운동별 완료 세트·중량×반복·볼륨과 동일 조건의 지난 기록 대비 변화. 행을 펼쳐 세트별 기록을 본다.
5. 별도 `세부 분석` 영역. 원본 수신·로컬 분석·AI 리뷰의 진행 상태와 이미 완료된 결과를 표시한다.
6. 화면 하단 완료/기록 보기. 분석을 기다리지 않고 나갈 수 있다.

총 볼륨은 완료 세트의 입력 중량×실제 수행 반복 합계다. `총 무게` 대신 제품 화면에는
`총 볼륨`과 kg 단위를 사용하고 설명에 계산 의미를 넣는다. 중량/반복 미입력을 0으로 만들지 않는다.
자중 운동, 보조 중량, 양손 덤벨 중량의 의미와 표시 단위를 운동 계약에 맞춰 유지한다.
완료한 모든 세트 수와 일반/웜업의 구분을 제공하며 증감 비교는 일반 세트 기준으로 계산한다.
운동 시간은 시작~종료 경과 시간에서 명시적 일시정지를 구분하며 실제 운동·휴식 시간을 따로 조회한다.
심박은 운동 중 미리 수집한 경량 시계열을 종료 기록에 보존해 대용량 IMU 수신 없이도 표시한다.
받지 못한 구간은 그래프를 끊고 `심박 일부 미측정`으로 표시한다. 결측을 0이나 가상 보간으로 채우지 않는다.
평균은 유효 표본과 시간 간격을 고려하고 최고 심박은 품질 검사된 실제 표본에서 계산한다.

## 추정 활동 칼로리

칼로리는 GPT를 호출하지 않고 폰에서 즉시 계산하는 추정치다. 세트수·중량·심박만으로
개인 에너지 소모를 정확히 환산할 수 있다고 표현하지 않는다. 체중과 측정일, 운동/휴식 시간,
운동 유형·강도 기준을 사용하고 심박은 측정 품질과 유효한 검증 방법이 있을 때 반영한다.
세트·반복·중량·RPE는 운동 구성과 강도 선택의 보조 정보다. kg×회에 임의 계수를 곱하지 않는다.

초기 대안은 출처 있는 운동별 MET 추정이다. 활동/휴식 구간별로
총 소모 kcal = MET × 3.5 × 체중kg / 200 × 분을 합산하고,
활동 칼로리에서는 같은 시간의 1 MET 기준 소모를 뺀다. 모델의 적용 연령·조건을 확인한다.
세트 시간 없이 경과 시간만 있으면 검증된 세션 평균 방식을 명시적으로 선택한다.
이미 검증된 플랫폼 운동 칼로리를 쓰는 경우 자체 추정과 중복 합산하지 않는다.

화면 라벨은 `추정 활동 칼로리`, 숫자는 `약 170 kcal`처럼 표시한다. 체중 등 필수 정보가 없으면
`프로필 입력 후 확인`으로 보여주며 가짜 기본 체중을 넣지 않는다. 계산 출처·버전·사용 프로필은 저장한다.
원본 심박이나 시간 보완으로 값이 바뀌면 갱신 이유와 revision을 보관한다.
미검증 심박 보정계수와 운동 후 추가 소모를 임의로 더하지 않는다.

근거: [2024 Adult Compendium 운동 강도](https://pacompendium.com/conditioning-exercise/),
[저항운동 중 웨어러블 에너지 소모 검증](https://pubmed.ncbi.nlm.nih.gov/29189666/).

## 세부 분석 상태와 문구

| 실제 상태 | 제목 | 보조 문구/동작 |
|---|---|---|
| 기대한 워치 원본을 수신 중 | 워치 기록을 받는 중이에요 | 실제 캡처 수를 알 때만 `7/9개 수신`; 연결 종료 시 재연결 안내 |
| 원본 수신·검증 후 로컬 계산 중 | 속도와 움직임을 분석하고 있어요 | `운동 기록은 저장됐어요. 이 화면을 나가도 분석은 계속돼요.` |
| 실제 GPT 요청 실행 중 | AI 코치가 운동 리뷰를 정리하고 있어요 | 취소 가능. 완성된 센서 지표는 먼저 표시 |
| 일부 원본만 확보 | 일부 세트의 분석이 남아 있어요 | 완료된 결과와 누락 세트를 함께 표시하고 재연결/재시도 제공 |
| 미지원 운동·원본 없음 | 이 운동은 세부 측정을 하지 않았어요 | 수동 수행 기록은 그대로 표시. 존재하지 않는 로그를 기다리지 않음 |
| 시간 초과·오류 | 세부 분석을 아직 마치지 못했어요 | 기록 유지, 실제 실패 단계와 재시도 동작 표시 |
| 완료 | 세부 분석 | 템포·관측 가능한 움직임 변화·AI 리뷰를 근거와 함께 표시 |

`에이전트가 분석 중이에요`는 실제 모델 작업이 실행 중일 때만 사용할 수 있다.
기본 문구는 이용자가 이해하기 쉬운 `AI 코치`를 사용하고 단순 파일 수신·수치 계산과 구분한다.
`잠시만 기다려주세요` 반복 대신 화면을 나가도 된다는 행동 정보를 제공한다.
처리량을 알 수 없으면 작은 진행 표시와 단계명만 쓴다. 시간/퍼센트를 만들어 표시하지 않는다.
분석 완료 결과가 생기는 항목부터 채우며 전체 영역을 같은 스켈레톤으로 오래 비워두지 않는다.

워치 전체 로그는 세션/세트/시도 ID와 원본 manifest를 기준으로 기대 목록을 확정한다.
세트 수를 원본 개수라고 가정하지 않는다. 세트 분할 캡처·수동 운동·중단 기록을 구분한다.
앱 종료·재연결·프로세스 재시작 후 상태와 완료 결과를 복구하고 같은 분석을 중복 요청하지 않는다.
GPT 요청은 공통 실행기의 제한·한도·취소 처리를 사용한다. 결과 화면의 즉시 요약은 그 실패와 독립적이다.
늦은 재분석으로 자동 횟수/볼륨이 갱신되면 한 번 `세부 분석을 반영했어요`로 알려주고
직접 수정한 횟수는 유지한다. 이미 확정된 수치가 매 프레임 흔들리거나 바뀌지 않게 한다.

## 화면과 움직임

### 분석 완료 후의 내용

완료 결과는 템포 숫자 두 개와 일반적인 칭찬으로 끝내지 않는다. 앱이 제공한 운동/세트별
측정·이전 기록·사용자 목표를 바탕으로 `workout_review` v2의 검증된 LLM 응답을 표시한다.
시안의 모든 분석 문장은 예시 payload이며 실제 앱에 그대로 하드코딩할 최종 리뷰가 아니다.

1. **오늘의 핵심:** 1~3개 변화와 전체 판단. 볼륨 증가가 어느 운동의 반복/중량/세트 변화에서 왔는지 설명한다.
2. **운동별 분석:** 완료한 모든 운동을 목록으로 보여준다. 각 행의 한 줄 결론을 누르면
   이전 대비 변화, 올림/내림/정지 시간, 후반 변화, 측정 횟수 차이, 관측 가능한 움직임 정보를 펼친다.
3. **문제가 생긴 구간:** 특정 세트/반복의 변화를 지정하고 첫/마지막 세트 비교나 반복 시간 그래프를 제공한다.
   어떤 데이터에서 읽은 결론인지 `분석 근거 보기`에서 수행 기록·센서 구간·촬영 관측 범위를 확인한다.
4. **다음 운동 행동:** 우선 1~2개의 중량/반복/템포 유지·변경 또는 추가 확인/보정 제안과 이유를 보여준다.
   사용자의 목표·노력 기록·실제 증량 단위에 맞춰 제안하고 자동으로 운동 계획이나 보정값을 변경하지 않는다.
5. **확인 범위:** 분석한 세트/기록/원본과 카메라 유무를 짧게 표시한다. 관측값·해석·자료 부족을 구분한다.

평균 값만 비교하지 않고 per-set/per-rep 특징을 제공한다. 총 볼륨 증가를 근육 성장률로,
손목 회전폭 감소를 팔꿈치 가동범위 부족으로, 느린 반복을 피로/RIR 확정으로 바꾸지 않는다.
촬영이 있으면 관측 가능한 자세 지표도 설명하되 없는 영상이나 미관측 부위를 채워 넣지 않는다.
자료가 부족한 운동도 목록에서 사라지지 않으며 부족한 항목과 다음 확인 방법을 알려준다.

숫자와 그래프는 앱에서 계산한 metric ID를 기준으로 표시하고 LLM은 그 변화의 의미·가능한 원인·
개인에게 필요한 행동을 연결한다. 요청마다 완료한 운동 전체를 입력에 넣고 요약 문구를 상황에 맞게 생성한다.
한 번의 제한된 리뷰 요청으로 결과를 구조화하며 운동마다 별도 호출로 대기 시간을 늘리지 않는다.
긴 내용을 모두 펼쳐 놓지 않고 요약과 중요한 운동부터 읽고 필요할 때 상세/근거를 확인하게 한다.

### 운동 제목 왼쪽 애니메이션 (2026-10-14 추가)

운동 기록과 세부 분석의 운동별 목록 모두 제목 왼쪽에 같은 52dp 정사각형 애니메이션을 배치한다.
애니메이션과 검은 빈칸 모두 하단 운동 기록 보기 버튼과 같은 모서리 반경 6dp를 사용하고, 이미지도 같은 모양으로 클리핑한다. 시안에서는 동일한 6px radius 토큰을 공유한다.
두 목록의 이미지는 검증된 exerciseId로 앱의 `exercise_<id>` drawable 리소스를 찾는다.
제목 문자열이나 목록 순서로 매칭하지 않는다. 애니메이션이 없거나 읽기에 실패하면 같은 크기의
검은 네모 빈칸을 유지하고 나중에 해당 운동 리소스를 추가하면 표시되게 한다.
다른 기구/변형 운동의 애니메이션을 임의로 대신 넣거나 기존 인체 placeholder를 표시하지 않는다.

시안의 벤치(`flat_bench`)와 랫풀(`lat_pull_down`)에는 앱에 있는 GIF 원본을 연결했다.
덤벨 컬(`dumbbell_curl`) 전용 리소스는 현재 없어 검은 빈칸으로 남겼다.
기존 `exerciseAnimationView`의 리소스 조회·표시 방식을 재사용하되 결과 목록의 missing fallback은
검은 네모로 한다. 각 뷰는 독립 디코더를 사용하고 화면 밖/앱 비활성 상태에서는 재생을 정지한다.
이미지 로딩/애니메이션 때문에 행 높이나 제목 위치가 바뀌지 않게 크기를 먼저 확보한다.
390px·큰 글씨에서 운동명·중량·상세 펼침 동작이 잘리지 않는지 함께 확인한다.

현재 K코치의 어두운 배경·민트 포인트·타이포·간격을 사용한다. 숫자는 강하게, 단위는 작게 두고
Fleek 참고 명세의 볼륨 요약·이전 기록 비교·접히는 세트표 구조를 활용한다.
운동별 정보는 구분선과 목록으로 정리한다. 색은 심박 곡선·중요 변화·진행 상태에 집중한다.
상단 기록이 아래 분석 갱신 때문에 밀리지 않도록 분석 영역의 최소 높이와 단계별 자리 배치를 정한다.
상태 변경은 현재 공통 200~300ms 모션을 사용하고 긴 결과 전체의 반복 등장 애니메이션은 하지 않는다.
접근성 설정에서 모션을 줄이고 큰 글씨/390px 화면에서도 값·단위·동작이 잘리지 않게 한다.

## 완료 기준

- 즉시 요약은 GPT/전체 IMU 수신 없이 나타나고 저장 기록·단위·완료 세트 합계와 일치한다.
- 심박 공백/미수신/프로필 미입력이 각각 정상 숫자와 구분되고 칼로리 계산법이 재현 가능하다.
- 수신 중→로컬 분석→GPT 리뷰→완료, 일부 결과, 미지원, 취소/시간 초과를 실제 상태로 구동한다.
- 화면 이탈/앱 재시작/재연결 뒤 이어지고 완료한 분석은 재호출하지 않는다.
- 수동 수정과 늦은 분석의 우선순위, 이전 기록 비교 조건, 숫자 갱신 이유를 확인한다.
- 리뷰에 완료 운동 전체가 포함되고 변경된 세트·근거·구체적 다음 행동이 연결된다.
  동일 기록에는 일관된 수치가, 다른 기록/목표에는 다른 해석이 나오며 공통 고정 리뷰 문장으로 대체하지 않는다.
